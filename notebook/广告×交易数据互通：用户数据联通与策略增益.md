# 广告×交易数据互通：用户数据联通与策略增益

> 缘起：2026-09-28 听到的一个业务——「广告和交易是两个大部门，数据不互通，老板希望数据互通，
> 实现用户数据联通，通过行为数据形成行为数据标签，实现更精准的策略，提升转化和收益」。
>
> 这段话是一条**被压缩的商业逻辑链**：老板说的是结果，中间省略了至少四个环节。本文把它展开成
> 「背景 → 目的 → 动作 → 收益」的完整结构，并补上技术深挖点（ID-Mapping / 延迟反馈 / 增量建模）。
>
> 定位：本文是 `notebook/AI 数据策略：从 AiMe 到 B 端 Agent 平台`（数据策略五问）在**互联网广告 × 电商**
> 场景下的实例，也是 `notebook/AI 数据策略 PM 工作闭环`（评测驱动闭环）在**策略域**的对照案例。
> 与我的职业主线「评测 × 数据交叉点」直接咬合——见第九节。

## 零、一张图：这条链在讲什么

```text
【割裂态】
  广告部门 KPI：广告收入 / 消耗 / eCPM / 广告主 ROI
  交易部门 KPI：GMV / 订单 / 转化率 / 复购
        ↓ 数据不互通
  广告只知道"用户点了"      交易只知道"用户买了"
        ↓
  ★ 没人知道"点了广告的那个人，后来买了什么" ★
        ↓
  同一个用户在两个部门眼里 = 两个"半身人"

【打通态】
  组织割裂 ─→ 数据割裂 ─→ 用户视图割裂 ─→ 策略只能做"半程"
        ↓ 打通
  ID 打通 → 行为融合 → 标签体系 → 策略升级 → 转化/收益提升
```

一句话：**把"两个半身人"合成一个完整的人，让广告能投给"会买的人"，让交易能接住"被广告拉来的人"。**

但这句话有两个隐藏的坑，全文会反复回到它们：

```text
坑一：数据互通本身不产生收益 ← 见第四节末
坑二：能看到"谁买了" ≠ 能投准"谁会买" ← 相关性 ≠ 增量，见第六节
```

## 一、背景：为什么是两个大部门、为什么不通

### 1.1 三层原因（组织 / 技术 / 合规）

| 层面 | 具体原因 |
|------|---------|
| **组织层** | 广告 = 变现侧（客户是广告主），交易 = 电商侧（客户是商家和消费者），通常是两个独立 BG/事业部。各自有 OKR，数据**既是资产也是壁垒**——"我的数据变成公共资源，收益算谁的？" |
| **技术层** | ① **ID 体系不同**：广告侧是设备维度（OAID/IDFA/CAID，未登录也能投），交易侧是账号维度（登录 user_id + 订单）② 数仓不同、埋点口径不同、时间粒度不同 ③ **时效不同**：广告出价是 100ms 级，交易是准实时/T+1 |
| **合规层** | PIPL / 数据安全法：跨部门流转需**授权 + 脱敏 + 最小必要**；ID 关联本身触及隐私红线（设备 ID ↔ 账号 ID 的映射尤其敏感）；再叠加商业敏感（商家经营数据、竞对信息） |

> 这三层的难度是递**减**的：技术最容易（工程问题有确定解），组织最难（利益分配没有标准答案），
> 合规是**一票否决**（出事就是大事故）。真实项目里，卡住进度的大多不是技术。

### 1.2 不通带来的具体业务痛点（这段最关键）

| 侧 | 现状痛点 | 缺失的东西 |
|----|---------|-----------|
| **广告** | 只能优化点击、加购、表单这类**浅层转化**。广告主投了钱，不知道带来多少真实成交 → 不敢加预算 / 不敢开深度目标 | **后链路转化标签**（成交 / 复购 / 退货） |
| **交易** | 新用户冷启动难，不知道用户从哪来、在站外看了什么；推荐只能吃站内行为 | **站外 / 广告域的兴趣与意图信号** |
| **平台** | 同一用户拼不起来，画像割裂：广告域看到"爱看美妆的人"，交易域看到"买过三次口红的人"，**不知道是同一人** | **统一用户视图（One ID）** |

### 1.3 一个具体的因果故事（用来向别人解释为什么要打通）

```text
用户在抖音刷到某奶粉广告 → 点了，但没立刻买
        ↓（3 天后）
在商城搜"婴幼儿奶粉" → 加购 → 下单

广告侧看到：一次点击，无转化 → 模型学到"这类人不转化" → 下次压低出价
交易侧看到：一次自然搜索成交 → 归因为"搜索推荐效果好"
        ↓
真相：这笔成交是广告带来的，但两个部门都没看到完整链路
     → 广告被低估（预算流向别处）+ 搜索被高估（资源错配）
```

**这就是"归因断裂"**——不只是少了个标签，而是**两个部门的决策都被系统性带偏**。

## 二、目的：从手段到终局的五层

```text
① 破孤岛：ID 打通（Identity Resolution）→ One ID
      ↓
② 汇行为：广告曝光/点击 + 交易浏览/加购/下单/支付/退款/复购
        → 融合成统一行为序列
      ↓
③ 建标签：从行为中提炼标签体系（老板原话里的"行为数据标签"）
      ↓
④ 升策略：广告侧深层转化出价 + 人群定向；交易侧冷启动/推荐/召回
      ↓
⑤ 收收益：广告收入 + 交易 GMV 双增，用户 LTV 提升
```

### 2.1 「行为数据标签」具体长什么样（老板没说、但必须定义清楚）

```text
├── 事实标签：近 30 天购买母婴品类 3 次
├── 兴趣标签：美妆 / 母婴 / 3C / 户外
├── 意图标签：高购买意向、比价中、待决策
├── 价值标签：LTV 分层、消费力等级、价格敏感度
└── 生命周期标签：新客 / 活跃 / 沉默 / 流失预警
```

### 2.2 标签的分类口径（工程上要区分对待）

| 类型 | 生成方式 | 举例 | 时效 | 维护成本 |
|------|---------|------|------|---------|
| **事实标签** | 直接统计 | 近 30 天购买 3 次 | T+1 | 低 |
| **规则标签** | 人工规则 | 消费力 = 近 90 天 GMV 分位 | T+1 | 中（规则会腐化） |
| **模型标签** | 模型预测 | CVR、LTV、流失概率、兴趣向量 embedding | 实时/准实时 | 高（要持续训练） |

> 三类标签的**评估口径完全不同**：事实标签看准确率（口径对不对），规则标签看业务合理性（人 review），
> 模型标签看 AUC / GAUC + **增量价值**（加了这个标签，模型或实验涨了多少）。

## 三、动作：数据层 → 标签层 → 策略层

这三层是**真实的依赖顺序**，不能跳。绝大多数"数据中台"失败在做完 L1 就停了。

### L1 数据层（地基，最重最慢）

```text
├── ID-Mapping / One ID                              ← 技术深挖点，见第六节
│   ├── 主锚点：登录态 user_id
│   ├── 关联对象：设备 ID、广告 ID、支付 ID、手机号(哈希)、会员 ID
│   ├── 算法：图计算求连通分量（Union-Find），输出映射表 + 关联置信度
│   └── 难点：多设备、多账号、家庭共用设备、模拟器/黑产、ID 漂移
│
├── 合规前置（能不能做的前提，不是"后面再补"）
│   ├── 用户授权、脱敏、数据分级分类
│   └── 隐私计算：联邦学习 / MPC（多方安全计算）/ TEE（可信执行环境）
│       └── 用途：让"数据可用不可见"，是跨部门/跨公司的破局手段
│
├── 统一事件模型
│   └── 曝光/点击/加购/下单/支付/退款，统一埋点口径与时间戳
│   └── 难点：两边"下单"的定义可能都不一样（拍下？付款？发货？）
│
├── 双链路（Lambda 架构）
│   ├── 离线：T+1 特征供模型训练
│   └── 实时：成交事件几分钟内回流广告模型 ← 延迟反馈的根源在这，见第六节
│
└── 特征存储（Feature Store）
    ├── 在线：Redis/HBase，P99 < 10ms（广告请求 100ms 内必须取到标签）
    ├── 离线：Hive/ClickHouse，供训练
    └── ★ training-serving skew：在线离线特征必须一致，这是推荐/广告系统的经典坑
```

### L2 标签层（中间产物，也是"数据产品"本体）

```text
├── 标签生产：事实 / 规则 / 模型三类（见 2.2）
├── 标签治理：覆盖率、准确率、新鲜度、血缘监控
│   └── 覆盖率是隐蔽杀手：标签只覆盖 30% 用户 → 策略只能在 30% 流量上生效
├── 标签服务化：DMP / 标签平台
│   └── ★ 关键设计：同一套标签，供广告定向和交易推荐**同时**消费
│       —— 这才是"互通"的价值兑现点，否则只是搬了份数据
└── 权限与审计：谁能查什么标签、查了留痕
```

### L3 策略层（价值兑现）

| 侧 | 具体策略 |
|----|---------|
| **广告** | ① **深层转化出价**：oCPM 目标从"加购"下移到"支付成交" ② DMP 人群包定向（"近30天买过母婴"→推奶粉）③ Lookalike 扩量、RTA ④ 跨域归因窗口定义 |
| **交易** | ① 新客冷启动：用广告域兴趣补足 ② 搜索意图纠偏 ③ 复购唤醒 / 流失召回 |
| **验证** | ① AB 实验（注意跨域 spillover 污染）② 因果推断（PSM/DID）③ **Uplift 建模找增量**（见第六节） |

### 3.1 推进节奏（PM 视角：分阶段交付）

```text
P0  合规 + ID 打通（小流量可行性验证，先证明技术上做得出来）
      └── 交付物：ID 映射表 + 覆盖率/准确率报告
P1  标签体系 MVP（先做 3-5 个核心标签，广告侧先用）
      └── 交付物：标签平台 v1 + 标签质量看板
P2  策略应用（深层转化出价上线 + AB 实验）
      └── 交付物：一个跑通的收益证明（这是项目能不能活下去的关键）
P3  规模化 + 双向（交易侧也开始消费广告域信号）
      └── 从"广告蹭交易数据"变成"双向互喂"
```

> **P2 是生死线**：P0/P1 是成本中心，只有 P2 产出一个被验证的收益案例，项目才从"数据中台"变成"业务引擎"。

## 四、预期结果收益

| 维度 | 观测指标 | 预期方向 |
|------|---------|---------|
| **广告** | eCPM、深度转化率、广告主 ROI、消耗、客户续费率 | 转化成本 CPA ↓ / ROI ↑ / 预算↑ |
| **交易** | 新客 CVR、冷启动时长、推荐 CTR/CVR、复购率、GMV | GMV ↑ / 冷启动从数天缩到 1-2 天 |
| **平台** | 总营收、用户 LTV、跨部门协同效率 | 双增 |
| **成本** | 合规投入、组织协调、算力、用户体验 | 负向项，需对冲 |

> 具体提升幅度必须靠实验测出来，任何"行业说能涨 X%"都是参考量级，不能当结论用（策略视角的基本纪律）。

### 4.1 ★ 核心判断：数据互通本身不产生收益

```text
数据互通 → 只是把"可能性"打开了
              ↓
真正产生收益的是三段接力：
   标签质量  ×  策略设计  ×  实验验证
      ↓            ↓            ↓
   覆盖/准/新    用对场景     证明是增量不是自然增长
```

**很多公司做了数据中台却没有收益，就是卡在这里**：L1 做完了，L2/L3 没人会用；或者用了，但没人验证
收益是否真实。这是这个项目最需要在立项时就对齐的认知。

### 4.2 风险清单

```text
├── 组织风险：收益怎么分？"数据是我的，收益是你的" → 需要内部结算机制
│   └── 这是最可能让项目死掉的原因，排在技术风险前面
├── 合规风险：隐私红线，出事是大事故 → 一票否决项，最高优先级
├── 策略风险：
│   ├── 回音壁效应：只推用户已买过的品类，越推越窄
│   ├── 标签固化：用户被永久打上"低消费"标签，再无翻身机会 → 需要标签衰减/复活机制
│   └── 过度打扰：全域触达 = 全域骚扰，用户体验是护栏指标
└── 统计风险：混淆变量导致收益被高估（见第六节）
```

## 六、技术深挖点（值得单独做八层解剖的三个）

### 6.1 ID-Mapping：图连通分量 + 置信度

```text
建图：G = (V, E)
  V = 各类 ID 节点（device_id / user_id / phone_hash / pay_id / ad_id）
  E = 可观测的关联边（同一设备登录过 A 和 B；同一手机号绑定过 X 和 Y）

求解：连通分量（Union-Find / Spark GraphX ConnectedComponents）
      → 同一连通分量内的 ID 判为同一人
```

**但有三个必须处理的坑**：

```text
① 传递闭包过度合并
   A~B, B~C ⇒ A~C，但关联强度逐跳衰减
   → 对策：限制最大跳数（实践常取 2-3 跳）+ 边上带权重/置信度

② 冲突消解
   一台设备被 5 个账号登录 → 家庭共用设备？还是黑产/模拟器？
   → 对策：规则 + 模型判别；异常簇直接标黑不合并

③ 评估缺 ground truth
   → 对策：用"同一订单里的 device 与 user"这类**天然成立的关联**做正样本，
           构造评测集算 precision / recall
```

> ★ 这里可以直接复用我在 CoT 质检项目里的方法：**Cascading Classification** —— 高置信规则先过
> （强关联直接合并），低置信的走模型判别，最后人工兜底。质量和成本的分层是同一套思路。

### 6.2 延迟反馈（Delayed Feedback）：广告侧的经典难题

```text
问题：t 时刻曝光，成交可能发生在 t+7d
      但在 t+1 训练时，这条样本的标签还是"负"（未成交）
      ——实际是"未知"，却被当成"确定不买"

数学刻画（样本被截断 / censored）：
      真实标签 y ∈ {0,1}，转化延迟 τ
      观测标签 ỹ = y · 1{τ ≤ e}     （e = 已观测时长）
      → 观测到的负样本 = 真负 ∪ 假负（还没转化的）

危害：每条假负样本都在教模型"这类人不买"
      → 系统性压低出价 → 广告主拿不到量 → 预算流失
```

**三种解法对比**：

| 方案 | 做法 | 优点 | 代价 |
|------|------|------|------|
| **等待窗口** | 等 7 天再训练 | 简单、标签干净 | 新鲜度差，新数据进不来 |
| **延迟反馈模型（DFM）** | 联合建模 P(转化) 与 P(延迟\|转化)，用 importance weighting 校正假负 | 兼顾新鲜度与准确 | 模型复杂度↑，实现难 |
| **短窗口 + 校准** | 用短窗口标签训练，再做概率校准 | 工程简单 | 校准不准会引入新偏差 |

> 高分回答：能说出"观测标签是 censored 的"，并指出**假负样本会系统性压低出价**，
> 而不只是"等久一点就好了"。

### 6.3 ★ 相关性 ≠ 增量：Uplift 建模（本文最深的洞察）

```text
数据互通后，我们能看到"谁买了"
但投放要准，需要知道的是"谁因为广告才买"——这是两件事

用户四分（Uplift 视角）：
  ┌─────────────────────┬─────────────────────┐
  │ 转化      不转化     │                      │
  ├─────────────────────┼─────────────────────┤
  │ 说服型    自然转化型 │ ← 广告触达         │
  │ (广告有用) (本来就买)│                      │
  ├─────────────────────┼─────────────────────┤
  │ 无动于衷  反感的     │ ← 广告未触达       │
  │ (投了没用) (投了更差)│                      │
  └─────────────────────┴─────────────────────┘

只有"说服型"是广告的真实增量。传统 CVR 模型只预测 P(买)，
会把大量预算浪费在"本来就买"的自然转化型身上。
```

**混淆变量的陷阱**：

```text
观察：广告域活跃的用户，交易域买得也多
诱人结论：广告有效
真相：可能只是"高消费用户本来就既爱看广告又爱买"
      → 混淆变量 = 用户固有消费力
```

**对策（策略视角的工具箱）**：

```text
├── AB 实验：黄金标准，直接测增量（但广告场景有 spillover、滞后效应问题）
├── PSM（倾向性得分匹配）：构造可比的实验组/对照组
├── DID（双重差分）：消除时间趋势和组间固有差异
└── Uplift 模型（Causal Forest / 双模型 / 元学习器）：直接建模增量，用于定向排序
```

> **这一节是整篇文章的"下一层"**：别人讲数据互通停在"打通 ID、建了标签、上了定向"，
> 你能往下讲一层——"我们优化的到底是相关性还是增量？"这是策略 PM 和数据分析师的分水岭。

## 七、工业界对标

| 公司/生态 | 做法 | 值得学的点 |
|-----------|------|-----------|
| **阿里**（阿里妈妈 × 淘宝天猫） | 同属一个体系，OneData 数据中台 + 达摩盘 DMP + 生意参谋 | 数据互通做得最彻底：广告与交易本就是一家，省掉了最大的组织阻力 |
| **字节**（巨量引擎 × 抖音电商） | 全域兴趣电商：内容场 + 搜索 + 商城；人群资产模型（5A：Aware→Appeal→Ask→Act→Advocate） | **双向闭环**：广告帮电商拉新，电商成交数据反哺广告出价——"广告主能看到真实 GMV"是加预算的前提 |
| **腾讯** | 微信广告 + 小程序电商/视频号小店 | 数据打通相对保守的反例：生态内烟囱多，但也因此合规风险最低 |

**规律**：广告与交易在**同一家公司体内**时，数据互通是"愿不愿意做"；在**跨公司**时，只能靠
隐私计算（联邦学习/MPC）做"可用不可见"——这是同一命题的两个难度档位。

## 八、讲述故事

### 30 秒版

> 广告和交易是两个独立部门，数据不互通，导致广告只能优化点击这类浅层转化、交易侧新客冷启动难。
> 老板想做的事本质是：通过 ID 打通和行为数据融合，建立统一用户视图和标签体系，让广告能投给
> "会买的人"、让交易能接住"被广告拉来的人"，最终广告收入和 GMV 双增。核心难点不在技术，
> 而在合规、组织利益分配，以及"怎么证明收益真的是互通带来的"。

### 2 分钟版（在 30 秒版上补三层）

```text
① 三层动作：ID-Mapping（图连通分量+置信度）→ 标签体系（事实/规则/模型三类）
           → 策略应用（广告深层转化出价 + 交易冷启动）
② 一个关键判断：数据互通本身不产生收益，是"标签质量 × 策略设计 × 实验验证"三段接力——
   很多公司做完数据中台没收益，就是卡在 L1 做完、L2/L3 没人会用
③ 一个最深的问题：能看到"谁买了"不等于能投准"谁会买"——
   相关性 vs 增量的区分（Uplift 建模），这是这个业务真正的技术天花板
```

### 高频追问与接法

| 追问 | 接法 |
|------|------|
| "数据不互通，那怎么解决？" | 三层拆：技术（ID-Mapping + 统一事件模型）、合规（授权脱敏 + 隐私计算）、组织（收益分配机制，最难） |
| "怎么证明有效果？" | AB 实验 + 因果推断（PSM/DID）；警惕混淆变量——高消费用户本来就既看广告又爱买 |
| "最大的风险是什么？" | 不是技术，是组织利益分配 + 合规红线；技术上有延迟反馈、training-serving skew 这些确定解 |
| "为什么广告主要关心这个？" | 因为他的钱花在"点击"上，但想要的回报是"成交"——归因断裂让他不敢加预算 |

## 九、和职业主线的连接

```text
① 这是「数据策略五问」在广告×电商域的实例
   采什么（广告+交易行为）/ 从哪采（两个部门数仓）/ 怎么用（标签→定向/出价）
   / 怎么验证（AB + 归因 + 因果推断）/ 优先级（P0 合规 → P3 双向）

② 评测与实验 = 这条链的最后一环 ★ 差异化定位的具体战场
   数据互通了、标签建好了、策略上线了——"怎么证明它真的带来收益"就是实验设计的活。
   别人讲数据互通只会讲"打通了 ID、建了标签"，我能往下讲一层：
   "我怎么设计实验证明这个标签真的有增量价值"。
   → 这正是「评测 × 数据交叉点」的落点，见 `notebook/AI策略产品与评测能力地图`

③ 方法论可直接复用（不是新学一套）
   ├── Cascading Classification → ID-Mapping 的分层置信合并
   ├── 能力 gap 驱动 → 数据互通是"归因断裂"这个 gap 的补法
   └── 评测驱动闭环 → 与本文 L3 的"验证"环节同构
```

> **面试锚点**：
> 「我理解这类数据互通项目的关键判断是：**数据打通本身不产生收益**，收益来自
> "标签质量 × 策略设计 × 实验验证"三段接力。而且打通的终点不是"知道谁买了"，
> 而是"知道谁因为广告才买"——这是相关性到增量的跨越，得靠 Uplift 建模和严格的实验设计。
> 这正好是我擅长的部分：把数据资产变成被验证过的收益。」
