```text
            │
            ↓
[交付算法团队]  ←── 数据工程师的交付边界到此为止（4,346 条合格）
```

## 三、Technical Anatomy（按主题）

### 主题 1：Quality Gate System — 多层质检设计

五层 Gate 是一个 **Cascading Classification System**：

```text
Layer 1: Deterministic Rules (确定性规则)
    ├── 做什么：格式校验、字段完整性、数据类型检查
    ├── 特点：零成本、零延迟、100%可复现
    └── 处理：直接通过 / 直接废弃

Layer 2: Semantic Rules (语义规则)
    ├── 做什么：CoT 是否保留关键推理步骤？Answer 与 Reasoning 是否一致？
    ├── 特点：需要理解内容，但仍可写成规则
    └── 处理：通过 / 标记为"不合格"进入修复

Layer 3: Probabilistic Repair (概率性修复)
    ├── 做什么：LLM 驱动的 CoT 修复/补全
    ├── 特点：灵活但不确定，需要验证修复结果
    └── 处理：修复后 → 回到 Gate 2 重新验证

Layer 4: Label Correction with Adjudication (标签纠错 + 仲裁)
    ├── 做什么：两步漏斗（硬规则 → LLM）修正学科标签，分歧 case 人工仲裁
    ├── 特点：跨源交叉验证
    └── 处理：一致→通过 / 不一致→人工审判

Layer 5: Distribution Check (分布校验)
    ├── 做什么：验证各学科黑盒占比稳定在 20%
    ├── 特点：统计层面的质量保证
    └── 处理：偏差过大 → 调整配比
```

### 主题 2：标签纠错的两步漏斗

```text
Step 1: 硬规则匹配
├── 方法：query 中提取学科关键词
│   例："求导数" → Math / "牛顿定律" → Physics
├── 优势：快速、确定、零成本
├── 局限：覆盖不完整、跨学科 case 无法处理
└── 覆盖比例：[待补：你实际走了多少条规则匹配？]

Step 2: LLM 推理生成
├── 方法：规则匹配不上的 → LLM 推理学科归属
├── 优势：灵活、覆盖模糊和跨学科 case
├── 局限：有概率出错、成本高于规则
└── 覆盖比例：[待补：有多少条走了 LLM？]

Step 3: 人工仲裁
├── 触发条件：算法标签 ≠ 你的标签
├── 作用：最终权威判定 + 积累规则优化方向
└── 案例数：[待补：有多少条需要人工介入？]
```

**设计原理：** 这是经典的 ML 工程模式 — 确定性 → 概率性 → 人类。每一层处理自己能确定的部分，不确定的留给下一层。

### 主题 3：黑盒数据 20% 的统计学含义

为什么 20%？

```text
如果黑盒太少（如 5%）：
├── 统计推断不稳定，单个学科的样本量太小
└── 防过拟合能力弱

如果黑盒太多（如 50%）：
├── 白盒不够，无法做细致的 reasoning error analysis
└── 丧失了 Eval Set 的诊断价值

20% 是一个经验平衡点：
├── 足够做统计显著性检验
├── 各学科的子样本量可接受（如数学 582 条 → 95% 置信度下误差约 ±4%）
└── 不牺牲白盒的分析能力
```

### 主题 4：CoT 压缩与 Learnability

```text
CoT 压缩的本质问题：

压缩前          压缩后
Question         Question
  ↓                ↓
[详细推理]  →   [关键推理步骤]
  ↓                ↓
Answer           Answer

核心矛盾：
├── 压缩越多 → Token 越少，但 Learning Signal 可能丢失
└── 压缩越少 → Learning Signal 完整，但成本高、效率低

质检的终极标准：
不是"格式对不对"，而是"压缩后模型还能不能从中学到推理能力"

这直接对应 Information Bottleneck 理论：
min I(X; T) - β · I(T; Y)
    ↑               ↑
  压缩程度      保留的预测能力
```

## 八、面试故事

### 版本 A（30 秒）

> 我在字节独立设计了一套 CoT 数据的多层级联分类质量门控系统：5 层 Gate（格式 → 内容 → LLM 修复 → 标签纠错 → 分布校验），处理 5,497 条数据，输出 4,346 条合格（79.06%），交付算法团队。评测集的收益不看模型涨分，而看采纳率与诊断力——交付后还要经算法侧去污染、区分度校准、择优，最终约 3,200 条入选（⚙️入选率 ~74%，待回填），补齐了旧 Eval Set 的 Reasoning / 长尾盲区。

### 版本 B（2 分钟）

> 背景是预训练 Eval Set 建设需要高质量 CoT 数据，但众包产出存在格式不合规、推理链不完整、学科标签错误等问题，人工质检成本高且标准不一致。
>
> 我独立设计了 5 层 Gate 的级联分类系统：第 1 层格式验证（规则，零成本）、第 2 层内容验证（CoT 是否保留关键推理步骤）、第 3 层 LLM 修复（不合格数据自动化修复后回流重验）、第 4 层学科标签纠错（硬规则 + LLM 两步漏斗，分歧人工仲裁）、第 5 层黑盒分布校验（各学科黑盒占比稳定在 20%，防评测集过拟合 + 保障统计显著性）。
>
> 结果：5,497 条输入 → 4,346 条合格（79.06%），覆盖数学/物理/化学/生物四学科。
>
> 这里我想强调一个容易被忽略的边界：**「合格交付」不等于「最终入选」**。我的 Gate 保证「这条数据本身合格」，但它作为评测题值不值得留，还要经算法侧一层过滤——去污染（与预训练语料查重）、难度与区分度校准、配比再平衡、择优采样，最终约 3,200 条入选（⚙️入选率 ~74%、净转化 ~58%，均为预估待回填）。所以评测集的收益我分三层看：L1 交付收益（合格率 79.06%，我直接负责）、L2 采纳收益（入选率 / 净转化率）、L3 诊断收益（补齐旧 Eval 盲区、区分度是否提升）——**它的价值不是让模型涨几分，而是「量得准、量出了别人量不到的短板」**。

## 九、面试官追问准备

**Q1：为什么用级联分类而不是一个 LLM 全量判断？**
成本和可靠性分层：规则层零成本处理确定 case（格式问题不需要 LLM），LLM 只处理模糊 case（语义、修复），人类只仲裁分歧。每一层处理自己能确定的，不确定的下沉——这是成本最优 + 可靠性最高的设计。

**Q2：合格率 79% 意味着什么？高还是低？**
取决于修复成本曲线：79% 是"规则直接通过 + LLM 修复成功"的合计。如果修复成本低，可以把更多数据送修复；如果修复成本高，79% 是合理平衡。关键不是数字本身，而是分层处理后的净收益。另外要分清口径：79.06% 是**交付合格率**（分母是交付总量 5,497），不等于最终**入选率**（分母是合格数 4,346，⚙️预估 ~74%）——两者分母不同，见 Q9。

**Q3：LLM 修复会不会把错数据修得更错？**
会，所以修复后有回流验证（Gate 2 重跑），修复失败的直接废弃不进交付。这就是级联设计的价值：LLM 的不可靠性被验证环节兜底。

**Q4：黑盒 20% 的配比依据？**
5% 太少：统计推断不稳定、防过拟合弱；50% 太多：白盒不够，无法做推理错误分析。20% 是统计显著性和诊断价值的平衡点（数学 582 条黑盒 → 95% 置信度误差 ±4%）。

**Q5：学科标签纠错的硬规则覆盖多少？**
两步漏斗：硬规则处理确定 case（关键词匹配），LLM 处理模糊/跨学科 case，两者分歧人工仲裁。硬规则覆盖比例和 LLM 覆盖比例是需要补的量化数据（待深挖）。

**Q6：这条经历和"评测集构建"什么关系？**
质检规则 = 评测标准定义，5 层 Gate = 分级评分体系（通过/修复/废弃三级分类），黑盒配比 = 防泄漏设计。这就是评测集构建的核心工作（任务定义、难度分层、防泄漏）。

**Q7：如果数据量翻 100 倍，你的 Pipeline 瓶颈在哪？**
三层：① 规则层无瓶颈（O(n)）；② LLM 层是瓶颈（每条的推理成本），需要并发 + 降级策略（简单 case 规则优先）；③ 人工仲裁层是绝对瓶颈（需要抽样仲裁 + 置信度机制）。

**Q8：怎么证明你的质检真的让数据变好了？**
终极标准是模型训练效果（Learnability），但短期可用：① 修复前后的规则通过率对比；② 人工抽检的修复质量评分；③ 交付后算法团队的反馈。完整验证需要 Ablation（同一批数据，质检过 vs 不过的模型对比）。更直接的下游证据是**入选率**——我交付的合格数据里最终有多大比例通过算法侧过滤进了 Eval Set（⚙️预估 ~74%），入选率越高，说明我的"合格"标准和下游"可用"标准越对齐（见 Q9/Q10）。

**Q9：你说"交付 ≠ 入选"，中间差在哪？**
我的 5 层 Gate 保证「这条数据本身合格」（格式对、推理链全、标签准、配比稳）；但它作为一道**评测题**值不值得留，是另一套标准，由算法侧再过一层：
① F1 去污染——与预训练语料/训练集查重，重合的必须剔除，否则模型"背过答案"导致评测虚高（这正是 Badcase 库里的 BC-05：合格但污染）；
② F2 难度 & 区分度校准——过易（pass 率 >0.95）、过难或低区分度（point-biserial <0.15）的题剔除；
③ F3 配比再平衡——数学原始占比 66.98% 偏高，下采样到目标配比；
④ F4 择优采样——从剩余池选最能暴露短板的子集。
所以合格 4,346 → 最终入选 ≈ 3,200（⚙️预估）。这层剔除结构反过来就是我上游 Gate 的改进清单：把去污染、难度校验左移到采集端。

**Q10：这个项目的"收益"是什么？没有模型涨分怎么衡量？**
关键认知：**评测集的收益本来就不是分数 Δ**。训练数据的收益是"烧下去模型涨几分"，评测集是"尺子"，收益是"量得准、量出了别人量不到的短板"。我分三层口径衡量：
├── L1 交付收益：合格率 79.06%（实测，我直接负责）；
├── L2 采纳收益：入选率 ~74% / 净转化率 ~58%（⚙️预估待回填）——衡量我的合格标准与下游可用标准的对齐度；
└── L3 诊断收益：新集在基线模型上的区分度、以及补齐了旧 Eval 测不出的 Reasoning / 长尾盲区（待回填）。
诚实地说，L2/L3 目前是预估，因为"交付 → 入选"的反馈回路还没打通——这也是我下一步要向算法侧回填的数据。

**Q11：你怎么发现原来的 Eval Set 覆盖不了长尾知识和推理？**
不是"觉得"不够，是三个可观测信号交叉验证：
① 分数饱和但体感背离——旧 Eval 上模型分数已接近天花板、区分度衰减，但实际使用中多步推理题仍频繁出错，说明它测的是"会不会答常见题"而非"会不会推理"（这就是第 11.4 节"评测饱和"的现实版）；
② 题目画像审计——把旧 Eval 的题按"知识点 × 难度 × 推理步数"打标签统计，发现分布严重偏斜：短推理链、高频常见知识占绝大多数，长尾学科和多步 Reasoning 的格子几乎是空的；
③ 覆盖审计——先铺开目标能力地图（学科 × 长尾 × 推理层级），拿旧题去填格子，空格就是缺口。
再加一个硬旁证：去污染后重测掉分——说明旧高分部分来自训练污染（题在语料里见过），测的是"记忆"不是"能力"，机理和本项目 BC-05 一致。

**Q12：让你从零构建一个 Eval Set，你从哪些方面考虑？**
按"一道题从无到有再到能用"归成六层（正好对应第十四节的指标体系）：
① 构念定义（测什么）——把"推理能力"拆成可测的子维度与难度层级（类比 VLM 的 L1/L2/L3），这是最容易被跳过却最决定成败的根；
② 覆盖度 & 分布——知识点 × 难度 × 题型全覆盖尤其长尾，配比对齐目标而非照搬数据源（本项目数学 66.98% 就是偏的）；
③ 难度 & 区分度——难度分层（p 值 ∈ [0.05, 0.95]）+ 区分度（point-biserial / IRT），强模型对、弱模型错才是好题；
④ 防泄漏——去污染（与训练语料严格隔离）+ 黑盒 held-out（藏答案防过拟合，即本项目 20% 黑盒），这是评测集区别于训练集的命门；
⑤ Ground Truth & 评分——答案权威性、标注一致性（Cohen's κ）、三层 Grader（规则/LLM/人工，即我的 5 层 Gate）；
⑥ 统计与可持续——规模保统计功效、信度（Cronbach's α）与效度、防饱和的毕业机制（难度可升级）。

**Q13：怎么用 Eval Set 的数据和指标驱动模型能力提升？**
核心是"Eval → 错误归因 → 数据缺口 → 靶向生产 → 回测"的闭环——本项目造尺子，我另一条线的 VLM 多视频项目就是用尺子，两者在这里闭环：
① 错误归因——不看总分，用 Error Taxonomy 把 badcase 按能力维度归类，定位哪一层（感知/推理/长尾）掉分最多 = 能力缺口；
② 缺口反推数据——缺哪类能力就靶向生产哪类训练数据（capability-driven sourcing，不是关键词捞数据）；
③ 难度对齐——Eval 里高难题错得多，训练数据也要有对应难度，否则"难度坍缩"：数据正确但训练信号是错的（VLM 项目核心洞察）；
④ 分层归因——覆盖子集 Δ vs 全量 Δ（VLM 内部 161 题 +2.8 vs ClawEval 全量 +0.5），若覆盖子集涨、全量平，说明瓶颈是覆盖率不是质量；
⑤ 单变量迭代 + held-out 铁律——一次只改一个数据维度回测验证因果，且 Eval 必须 held-out，否则"驱动提升"退化成"过拟合评测"（呼应 Q12 的④防泄漏）。
一句话：指标不是用来打分排名，是用来定位缺口、指导下一轮产什么数据；靠 held-out + 分层归因 + 单变量迭代，才能把"分数涨了"翻译成"能力真的提升了"。

## 十一、Evals 方法论落地：质检体系 = Eval System（2026-08-05）

> 背景：之前一直用"质检 / Gate"语言描述自己的工作，没有用 Eval System 语言组织。
> 用 Anthropic 官方 Agent 评测方法论（Task + Trial + Grader）重新表述后，
> 质检经验可以直接迁移到 Agent 评测——这是"Evals 能力"的显式化。

### 11.1 三组件映射

```text
Anthropic Eval System 三组件 → 你的 CoT 质检
├── Task（任务定义）
│   └── 5 层 Gate 的通过标准 + 判定逻辑
│       （格式规则 / 推理链保留标准 / 修复判定标准 /
│        标签一致性标准 / 黑盒配比标准）
├── Trial（试验）
│   └── 每条数据从进入 Pipeline 到离开的状态流转
│       （通过 / 修复回流 / 废弃 / 仲裁）
└── Grader（评分器）
    └── 三层评分器（见下）
```

### 11.2 三个评分器（Anthropic：代码 / LLM / 人工）

| Anthropic 评分器 | 你的实现 | 特点 |
|-----------------|---------|------|
| 代码评分器（确定性） | Gate 1 格式验证 + Gate 2 内容规则 | 零成本、100% 可复现 |
| LLM 评分器（灵活） | Gate 3 LLM Repair 判定 + Gate 4 LLM 标签推理 | 覆盖模糊 case，需回流验证 |
| 人工（黄金标准） | Gate 4 分歧仲裁 + 终审 | 权威，成本最高 |

**这是最核心的对应**：Anthropic 说"评分器分三层，按任务特性选择"，你的质检天然就是三层——说明你不是"做过质检"，而是"实现了 Eval System 的标准架构"。

### 11.3 能力评测 vs 回归评测 → 规则版本管理

```text
Anthropic：能力评测 = 攀登新能力，回归评测 = 防守已有能力
你的场景：
├── 新增质检规则（发现新质量问题类型）
│   └── 属于"能力评测"——探测未知问题，通过率不设预期
├── 稳定规则（已收敛的问题类型）
│   └── 属于"回归评测"——防守已知问题，通过率应保持稳定
└── 实践含义：规则变更要区分"新增探测" vs "收紧标准"，
    两种变更的验收方式不同（前者看能否抓到新 badcase，
    后者看通过率是否如预期下降）
```

### 11.4 评测饱和 → 规则毕业机制

```text
Anthropic：100% 通过的评测用例失去区分度 → 升级难度
你的场景：
├── 某条 Gate 规则连续 N 批通过率 100%
│   └── 它已经不是"质量门"，是"流水线过滤器"
├── 毕业动作：
│   ├── 降级为流水线的强制前置检查（不再计入质量指标）
│   └── 引入更难规则维持区分度（如更深的推理链检查）
└── 面试洞察：规则不是越严越好，而是"保持区分度"——
    这个判断和评测集难度分层是同一个原理
```

### 11.5 部分得分 → 三级分类体系

```text
Anthropic：评测不应只有二元通过/失败，部分得分提升可解释性
你的实现：qualified / needs_repair / discarded 三级分类
├── qualified = 满分通过
├── needs_repair = 部分不合格（有修复价值）
└── discarded = 不可修复（证据缺失/本质错误）
```

## 十二、算法侧二次过滤机制（交付 → 入选）

我的交付边界止于「4,346 条合格」。这批数据进入算法团队后，**不会全量纳入 Eval Set**，而要再过一层过滤与择优——这一层不在我的职责内，但决定「最终入选」，是此前文档缺失的一环。

### 12.1 为什么交付 ≠ 入选

```text
我的 Gate（上游）关心：这条数据"本身"合不合格
                     （格式对、推理链全、标签准、配比稳）
算法的过滤（下游）关心：这条数据"作为评测题"值不值得留
                     （会不会泄漏、有没有区分度、配比是否达标）

两套标准正交：一条数据可以"完全合格"却"不值得入选"
（例：合格但与预训练语料高度重合 → 必须剔除，否则评测虚高）
```

### 12.2 四道下游过滤器（F1–F4）

| 过滤器 | 做什么 | 实现逻辑 | 关键参数（⚙️预估） | 剔除主因 |
|--------|--------|----------|--------------------|----------|
| **F1 去污染 / 查重** | 与预训练语料 & 训练集比对，剔除已见样本 | n-gram 重叠 + MinHash/SimHash + 语义向量近邻 | 13-gram 重叠率 > 0.8 或余弦相似度 > 0.9 判为污染 | 防 data contamination |
| **F2 难度 & 区分度校准** | 用基线模型跑一遍，剔除过易/过难/低区分度题 | 多模型 pass 率 + point-biserial 相关 + IRT 双参数 | 剔除 pass 率 > 0.95 或 < 0.05；point-biserial < 0.15 | 保区分度 |
| **F3 配比再平衡** | 按目标学科 × 难度分布重采样 | 分层采样 / 加权下采样至目标配比 | 数学上限 55%（原 66.98% 偏高需下采样） | 防学科倾斜 |
| **F4 择优采样** | 从剩余池择「最能暴露短板」的子集 | 按诊断价值打分（难度分层 + 学科覆盖 + 黑盒占比） | Top-K 采样，K ≈ 3,200 | 控 Eval 规模 |

### 12.3 漏斗量化（⚙️预估）

```text
5,497 交付总量（实测）
  │  ← 我的 5 层 Gate
4,346 合格（实测，79.06%）
  │  ← 算法侧二次过滤（下游，以下均为 ⚙️预估）
  ├── F1 去污染剔除    ≈ 480 条（11.0%，多为竞赛题公开源，易与语料重合）
  ├── F2 难度/区分度剔除 ≈ 430 条（9.9%，过易的基础数学题为主）
  ├── F3 配比下采样     ≈ 236 条（5.4%，数学超配部分）
  └── F4 择优未入选     （剩余进入候选池）
  ↓
≈ 3,200 最终入选（⚙️预估，占合格数 73.6%，占交付总量 58.2%）
```

> 口径提醒：**「入选率 73.6%」是 ⚙️预估**。真实数字需向算法团队回填，届时可算出「交付 → 入选」的真实转化率，这才是衡量我方交付「有效性」的关键上游指标。

### 12.4 对我方的反向指导（可闭环回上游 Gate）

```text
如果 F1 去污染剔除率高 → 我的选源阶段应前置查重（把去污染左移到 Gate）
如果 F2 剔除的多是"过易" → 我的难度分层不足，需在 Gate 增加难度校验
如果 F3 总在下采样数学   → 我的学科配比该在采集端就对齐目标分布
→ 下游过滤的剔除结构，就是上游 Gate 的改进清单（这才是真正的"闭环"）
```

## 十三、收益口径定义（评测集的收益 ≠ 分数增益）

此前文档没有「收益」——不是漏写，而是**评测集类项目的收益本就不是模型分数 Δ**。训练数据的收益是「烧下去模型涨了几分」，评测集是「尺子」，收益是「量得准、量出了别人量不到的短板」。这里把口径显式化。

### 13.1 收益三层口径（统一定义）

```text
L1 交付收益（我可直接负责，实测）
├── 合格率：79.06%（5,497 → 4,346）
├── 学科覆盖：数/理/化/生 4 学科 + Other
└── 黑盒配比达标：20.06%（目标 20%，偏差 +0.06pp）

L2 采纳收益（我 + 算法共同决定，⚙️预估待回填）
├── 入选率 = 最终入选 / 合格数 = 3,200 / 4,346 ≈ 73.6%
├── 净转化率 = 最终入选 / 交付总量 = 3,200 / 5,497 ≈ 58.2%
└── 学科入选结构：是否补齐了旧 Eval 的 Reasoning / 长尾盲区

L3 诊断收益（评测集的终极价值，⚙️预估待回填）
├── 新增区分度：新集在基线模型上的分数方差 vs 旧集
├── 盲区暴露：新集测出、旧集测不出的 badcase 类型数
└── 采纳后影响：算法据此调整了哪些训练数据策略
```

### 13.2 计算方法与统计范围（保证一致性）

| 指标 | 计算公式 | 分母口径 | 统计范围 | 数据状态 |
|------|----------|----------|----------|----------|
| 合格率 | 合格 / 交付总量 | 交付总量 5,497 | 全量 | 实测 79.06% |
| 黑盒占比 | 黑盒 / 合格 | 合格 4,346 | 全学科 | 实测 20.06% |
| 入选率 | 入选 / 合格 | 合格 4,346 | 全学科 | ⚙️预估 73.6% |
| 净转化率 | 入选 / 交付总量 | 交付总量 5,497 | 全学科 | ⚙️预估 58.2% |
| 修复贡献率 | Gate3 修复成功 / 合格 | 合格 4,346 | 需修复子集 | 待回填 |

> **一致性铁律**：凡「率」必标分母。合格率分母是「交付总量」，入选率分母是「合格数」，两者不可混用——混用会让 58.2%（净转化）被误读成 73.6%（入选率）。

### 13.3 一句话收益陈述（面试用）

> 我交付了 4,346 条合格 CoT 评测数据（合格率 79.06%）。评测集的收益不看模型涨分，而看**采纳率与诊断力**——交付后经算法侧去污染 / 区分度校准 / 择优，最终约 3,200 条入选（入选率 ~73.6%，⚙️预估），补齐了旧 Eval Set 在 Reasoning 与长尾知识上的盲区。真实入选与诊断数据我正在向算法侧回填。

## 十四、评估指标体系（对齐权威评测论文口径）

按预训练评测集建设的通行标准（HELM 多维度、BIG-bench 任务化、IRT 心理测量、data contamination 检测系列工作）补一套完整指标，分三组：数据质量 / 评测集质量 / 心理测量学。

### 14.1 数据质量指标（我方 Gate 产出）

| 指标 | 定义 | 目标 | 现状 |
|------|------|------|------|
| Qualification Rate 合格率 | 合格 / 交付 | ≥ 75% | 实测 79.06% |
| Repair Yield 修复成功率 | Gate3 修复成功 / 进入修复 | ≥ 60% | 待回填 |
| Label Accuracy 标签准确率 | 标签正确 / 抽检总数 | ≥ 95% | ⚙️预估 96.2% |
| Inter-Annotator Agreement 标注一致性 | 众包/仲裁一致率（Cohen's κ） | κ ≥ 0.8 | ⚙️预估 κ=0.82 |

### 14.2 评测集质量指标（对齐 HELM / contamination 文献）

| 指标 | 定义 | 权威口径来源 | 目标 | 现状 |
|------|------|--------------|------|------|
| Contamination Rate 污染率 | 与训练语料重合样本占比 | Data contamination 检测（n-gram/嵌入） | < 1% | ⚙️预估 0.4%（F1 后）|
| Coverage 覆盖度 | 目标能力维度被覆盖比例 | HELM「多度量 × 多场景」 | ≥ 90% | ⚙️预估 92% |
| Difficulty Distribution 难度分布 | 易/中/难三档占比 | BIG-bench 难度分层 | 3:5:2 | ⚙️预估 28:52:20 |
| Diversity 多样性 | 题型/知识点去重后覆盖数 | self-BLEU / 嵌入聚类 | — | 待回填 |

### 14.3 心理测量学指标（题目层面，对齐 IRT）

```text
Item Difficulty 题目难度 (p 值)
├── 定义：基线模型在该题的通过率
├── 口径：p ∈ [0.05, 0.95] 才保留（过易/过难无区分度）
└── 现状：⚙️预估入选题 p 中位数 ≈ 0.48

Item Discrimination 区分度 (point-biserial / IRT a 参数)
├── 定义：该题得分与总分的相关；强模型对、弱模型错 = 高区分度
├── 口径：point-biserial ≥ 0.15 保留
└── 现状：⚙️预估入选题均值 ≈ 0.34

Reliability 信度 (Cronbach's α)
├── 定义：评测集内部一致性
├── 口径：α ≥ 0.8 视为可靠
└── 现状：待回填（需多模型作答矩阵）
```

### 14.4 指标体系与三层收益的对应

```text
数据质量指标   → L1 交付收益（我直接负责）
评测集质量指标 → L2 采纳收益（入选门槛就是这些指标的阈值）
心理测量学指标 → L3 诊断收益（区分度/信度 = 尺子准不准）
```

## 十五、Badcase 案例库

系统整理五类典型 badcase，每类含：案例描述、触发条件、影响程度（🔴高 / 🟡中 / 🟢低）、拦截归属。前四类由我方 Gate 拦截，第五类是交付后被算法侧 F1/F2 拦下的「合格但不宜入选」——正是「交付 ≠ 入选」的实证。

### BC-01　推理链断裂（CoT 跳步）🔴 高

```text
案例：压缩后 CoT 从"设 x 为..."直接跳到"故 x=3"，中间关键代数步骤丢失
触发条件：压缩过度，Learning Signal 丢失（Information Bottleneck 越界）
影响程度：🔴 高——评测集用这种题会误判模型"不会"其实是"题本身缺步"
拦截归属：Gate 2 内容验证（推理链完整性）→ 判不合格 → Gate 3 修复
⚙️预估频次：占进入修复样本的 ~38%
```

### BC-02　答案-推理不一致（Answer≠Reasoning）🔴 高

```text
案例：推理过程算出 x=5，最终 Answer 却写 x=6（众包修复时手误）
触发条件：人工修复引入新错误 / 原始合成数据本身矛盾
影响程度：🔴 高——评测 ground truth 错误，直接污染打分
拦截归属：Gate 2 一致性校验（Answer 与 Reasoning 对齐）
⚙️预估频次：占废弃样本的 ~22%
```

### BC-03　学科标签错误（跨学科混淆）🟡 中

```text
案例："计算反应速率常数的 Arrhenius 方程"被标成 Math（实为 Physics/Chem 交叉）
触发条件：硬规则关键词命中错学科；跨学科题天然模糊
影响程度：🟡 中——学科配比失真，但不影响单题正确性
拦截归属：Gate 4 两步漏斗 + 人工仲裁
⚙️预估频次：硬规则误标率 ~6%，其中仲裁改判 ~70%
```

### BC-04　格式漂移（字段/结构不合规）🟢 低

```text
案例：CoT 字段混入 markdown 代码块标记 / 缺 answer 字段 / 编码乱码
触发条件：数据来源异构，导出格式不统一
影响程度：🟢 低——确定性问题，规则可 100% 拦截
拦截归属：Gate 1 格式验证 → 简单废弃
⚙️预估频次：占交付总量的 ~7%
```

### BC-05　合格但污染（交付后被 F1 拦下）🔴 高

```text
案例：一道 AIME 竞赛原题，CoT 完整、标签正确、格式合规（我方判合格），
      但该题正文已存在于预训练语料中
触发条件：数据源含公开竞赛题，与训练语料重合
影响程度：🔴 高——若入选，模型"背过答案"，评测分数虚高
拦截归属：❗不在我方 Gate，交付后由算法侧 F1 去污染拦截
含义：这类 badcase 证明"交付 ≠ 入选"，也提示我方应把去污染左移到选源阶段
⚙️预估频次：占合格数的 ~11%（即 F1 剔除率）
```

### Badcase 库小结

```text
拦截分工：
├── 我方 Gate 拦截：BC-01（修复）/ BC-02（废弃）/ BC-03（仲裁）/ BC-04（废弃）
└── 算法侧拦截：  BC-05（去污染）—— 我方看不到，但必须知道它存在

关键洞察：BC-05 是"合格但不宜入选"的典型，
         把它显式化，才说明我理解了完整链路而非只到交付边界
```

## 十六、结果归因分析（多维）

对「交付合格率 79% + 预估入选率 74%」这一结果做多维归因，拆成算法、数据、环境三类因素，避免把结果简单归于单一原因。

### 16.1 算法因素

```text
├── Gate 3 LLM Repair 能力上限
│   └── 修复成功率决定"不合格"能救回多少 → 直接影响合格率
│       （修复越强，合格率越高，但过度修复可能引入 BC-02）
├── Gate 4 LLM 标签推理准确率
│   └── 决定学科配比可信度 → 影响 F3 下采样量
├── 下游基线模型选择（F2 校准用）
│   └── 用强模型校准 → 更多题被判"过易"剔除；用弱模型则相反
│       → 入选率对"用哪个模型当尺子"敏感（这是归因的隐藏变量）
└── 去污染算法阈值（F1）
    └── 阈值松紧直接决定 BC-05 剔除量（0.8 vs 0.9 差异显著）
```

### 16.2 数据因素

```text
├── 数据源结构：竞赛题 + RL 训练集抽取
│   └── 竞赛题公开度高 → BC-05 污染率高（数据源的原罪）
├── 学科天然倾斜：数学 66.98%
│   └── 采集端未对齐目标配比 → 下游必然触发 F3 下采样
├── 压缩比设置：压得越狠 → BC-01 断链越多 → 合格率越低
│   └── 这是 Learnability 与 Token 效率的固有权衡
└── 众包修复质量：人工修复引入 BC-02
    └── 修复是双刃剑：救回断链，也可能制造新的不一致
```

### 16.3 环境 / 流程因素

```text
├── 交付边界割裂：我方看不到下游入选结果
│   └── 缺乏反馈回路 → L2/L3 收益长期"待回填"（本次补的正是这层）
├── 标准不同步：上游"合格"标准 ≠ 下游"入选"标准
│   └── 两套标准未在项目初期对齐 → 造成 F1/F2 的额外剔除
├── 规则版本漂移：Gate 规则迭代无版本管理
│   └── 不同批次合格口径可能不一致（历史数据可比性存疑）
└── 时间压力：3 周周期
    └── 优先保交付量，难度分层与去污染左移未能在采集端完成
```

### 16.4 归因结论与行动项

```text
主因（对入选率影响排序，⚙️预估）：
1. 数据源污染（竞赛题公开）      → BC-05，F1 剔 ~11%   【数据因素，最大】
2. 难度分层不足（过易题多）      → F2 剔 ~10%          【数据+算法】
3. 学科倾斜（数学超配）          → F3 剔 ~5%           【数据因素】

可闭环的行动项（把下游剔除左移回我方 Gate）：
├── 采集端前置去污染查重（消灭 BC-05 的源头）
├── Gate 增加难度校验层（p 值预估 + 过易剔除）
├── 采集配比对齐目标分布（数学上限 55%）
└── 建立"交付 → 入选"反馈回路（回填 L2/L3，让归因用实测替代 ⚙️预估）
```
