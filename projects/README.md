我发现业务与开发其实不应该分开写，因为我现在的职责定位是ai数据工程师，工作流程就是从业务方得到需求，这里的需求是上游发现的模型在某些benchmark上的指标低或者能力不佳。那么就需要先进行需求拆解及调研补充模型所缺失的能力，那么就需要思考补充哪方面的数据、如何保证数据质量、以及如何快速构造相关的数据集用于模型训练。开发的pipeline就是服务于业务的能力，虽然pipeline不用交付，但是可以作为通用的基础设施以及其中的可插拔能力，可以服务于下一次的业务场景。整体来讲，对于数据的处理分为以下流程：数据检索、数据预筛选、数据获取、数据格式转化、数据集构造（主要指的是QA、VQA及其中caption、cot的构造）、数据集质检（根据rubric判定数据集构造的是否合理、如不合理则进行修正处理）、数据回扫（对修正后的数据再次质检）、数据交付、数据训练模型（交付给上游业务方后再进行数据处理、配比等动作进行模型训练，这里我不参与）、数据评测（利用交付数据训练后的模型再用相同的benchmark评测，观测是否有提升，以及如果有多个数据集或者多种训练方式则进行消融实验和abtest的评测）

## 项目文档结构

每个项目文档包含：

1. **项目概览** — 背景、目标、周期、数据规模
2. **核心工作内容** — 职责、设计决策、量化成果
3. **Technical Anatomy** — 按主题逐步解剖（持续追加）
4. **四视角展开** — PM / 算法 / 工程 / 策略
5. **面试故事** — 30 秒 / 2 分钟 / 5 分钟三层版本
6. **面试官追问准备** — 8-10 个高频追问
7. **知识连接** — 本项目涉及的知识树干节点
8. **待深挖方向** — 还没拆到八层深度的点

- 一个项目一个 `.md` 文件
