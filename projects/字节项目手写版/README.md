# 字节项目手写版 · 目录说明

> 定位：VLM 长视频数据方向的项目文档，包含一个通用数据获取基建，以及两个分别复用该基建的业务项目。
>
> **口径原则**：实践操作类视频获取项目与证据检索式数据合成项目相互独立。前者交付 500 条视频；后者以独立获取的 512 个视频为输入，产出 512 条 Caption、7,961 条 QA 和 6,306 条 CoT。两个项目的数据量不得串联、相加或互相替代。

---

## 一、项目关系

```text
                         ┌─────────────────────────────────────┐
                         │ 自研检索与抓取平台（通用基建）       │
                         │ 检索 / URL 解析 / 抓取 / 转码 / TOS │
                         └──────────────┬──────────────────────┘
                                        │ 提供通用能力
                    ┌───────────────────┴───────────────────┐
                    ▼                                       ▼
┌──────────────────────────────────┐   ┌──────────────────────────────────┐
│ 项目 A：实践操作类视频获取        │   │ 项目 B：证据检索式数据合成        │
│ 3000 候选 → 520 通过 → 500 交付  │   │ 独立获取 512 个视频               │
│ 产出：视频 + TOS + Metadata       │   │ 产出：Caption / QA / CoT          │
└──────────────────────────────────┘   └──────────────────────────────────┘
```

- **通用基建**：提供“能搜、能抓、能存”的原子能力，不绑定具体数据需求。
- **项目 A**：围绕实践操作类长视频执行需求定义、召回、筛选、抓取和交付。
- **项目 B**：根据已有视频样例做同类型扩展，并在 512 个视频上完成 Caption、QA 和 CoT 合成。

项目 B 会复用通用基建的检索与 Fetch 能力，但**不消费项目 A 的 500 条交付数据**。

## 三、逐项说明

### 1. 通用基建：自研检索与抓取平台

```text
├── 检索平台：多关键词并发召回，返回视频 URL + Metadata
└── Fetch 平台：解析 URL → 下载视频 → 转码 → 转存 TOS
```

两个业务项目中的“自研检索平台”“自研 Fetch 平台”“并发抓取、失败重试和 TOS 转存”均复用这套能力。具体检索目标、筛选规则和数据质量标准由各业务项目独立定义。

### 2. 项目 A：实践操作类视频获取 Pipeline

```text
需求定义 → Data Rubric → 候选检索（通用关键词 + Agent Query Expansion）
→ 多级预筛（标题规则 → Metadata/画质 → 抽帧 + VLM 内容质检）
→ 并发抓取 → 转码标准化 → TOS → 交付带 Metadata 的数据表
```

- 目标：500 条、30～90 分钟的实践操作类长视频。
- 结果：候选召回 3000 条，筛选通过 520 条，最终交付 500 条。
- 核心思想：采用 Cost-aware 多级过滤，先执行低成本规则，再执行高成本 VLM 内容判断。

该项目止于“合格视频 + Metadata + TOS”的数据交付，不承接项目 B 的 Caption、QA 和 CoT 产出指标。

### 3. 项目 B：证据检索式数据合成 Pipeline

该项目根据已有视频样例独立扩展同类型视频，并参考 ReWatch-R1 构造三类带时间戳的训练数据：

```text
样例 Caption → 关键词扩展 → URL 召回 → 抽帧筛选 → 512 个可用视频
                                                      ↓
Caption：低帧率语义切段 → 高帧率局部描述 → 时间戳重对齐
                                                      ↓
QA：C_detail 与 C_sum 对比差异生成 → 三层过滤
                                                      ↓
CoT：Reasoner 检索决策 → Observer 证据返回 → Convert 轨迹整理
```

独立结果口径：

- Caption：512 条。
- 高难度视频 QA：7,961 条。
- Video-grounded CoT：6,306 条。
- 每条 CoT 平均包含 2.3 个推理步骤、332.5 tokens。

模型指标属于数据交付后的**上游训练评测反馈**，用于验证数据方向，不纳入本项目的数据生产交付量，也不与项目 A 的 500 条视频指标合并。

## 四、口径检查规则

1. 提到 `3000 → 520 → 500` 时，只指项目 A 的实践操作类视频获取结果。
2. 提到 `512 / 7,961 / 6,306` 时，只指项目 B 的 Caption、QA、CoT 合成结果。
3. 项目 B 的 512 个视频来自该项目独立的样例扩展、筛选与抓取流程，不是项目 A 的 500 条视频。
4. SFT、RL 和 Benchmark 指标统一表述为“上游训练评测反馈”，不得表述为数据生产环节的直接产出。

阅读建议：先阅读基建文档理解通用能力，再根据需要分别阅读项目 A 的视频获取流程或项目 B 的数据合成流程。
