## TL;DR

- **项目定位**：vlm-agent 能力提升——**针对 Agent 基准（ClawEval / WildClawBench）指标偏低，诊断失分环节、靶向补数据来增强模型能力**。本详版聚焦其中「视觉理解 / 跨片段推理」这条杠杆能力线（诊断出的一大失分主因），能力按 L1/L2/L3（跨片段感知—对比—推理）递进。数据生产只是实现手段。
- **核心链路**：Agent 基准诊断（失分环节归因）→ 锁定视觉理解缺口 → 能力维度定义（L1/L2/L3）→ 靶向数据寻源与难度控制 → Training Signal Quality Gate → 行为引导 Rollout + SFT → 分层对照评测 → 收益归因 → 下一轮数据策略。
- **真实结果**：三套评测集——**内部 161 题**（自建，衡量视觉理解能力本身；靶向数据覆盖 72 题约 45%，覆盖子集 **+2.8**）、公开 **ClawEval**（通用/多模态 Agent 基准，端到端全量 **+0.5**）、公开 **WildClawBench**（真实世界长链路 Agent 基准，**+2.3**）。注意：`72/161` 与 `+2.8` 只属于内部集，不是 ClawEval 的口径。
- **视觉数据为何能抬升 Agent 基准（因果链，见 10.10）**：Agent 任务（如从足球视频剪精彩片段、从搜索结果找矛盾）内含"看懂界面/视频"的子步骤——诊断显示这一步常是失分主因；靶向视觉理解数据经 SFT 补齐该瓶颈 → 子步骤做对 → 端到端完成度上升。所以 ClawEval/WildClaw 是本项目的**目标基准**，视觉数据是**杠杆**。⚠️ 归因未隔离：共享 base model 上还并行训练着另一个独立项目"长视频复杂推理"的数据（见 `bytedance-长视频复杂推理能力建设.md`），Agent 基准涨分需消融才能把本项目视觉数据的净贡献与之分开。
- **反直觉结论**：首轮实验最大的发现不是"数据有效"，而是"**数据有效，但覆盖不足**"——瓶颈是覆盖率，不是单条数据质量。下一轮资源应从"提质"转向"扩覆盖"。
- **核心洞察**：**数据正确 ≠ 训练信号正确**。难度本身是训练信号的一部分（Difficulty Collapse），必须把"难度对齐"从质检后置项前移到采集 Gate。
- **叙事最大短板（第 10.5–10.9 节）**：当前只有"指标"没有"指标 → 能力"的映射——`+0.5 / +2.3` 只能说明"模型整体变好"，证明不了"我构建的 L1/L2/L3 多视频能力变好"。需补一层"能力 Taxonomy → Benchmark 子集 → 数据覆盖 → Pre/Post Δ → OOD Δ"的能力归因层。且 ClawEval / WildClaw 是**通用 / 真实世界 Agent 基准**（非纯视频理解），只有其中的多模态 / Video QA 子项与本项目直接相关，汇报应拆到子项而非只报 Overall。

## 一、项目核心定位：能力提升，不是数据生产

一句话定位：

> **针对 VLM 在多视频理解任务上的能力缺口，建立"模型诊断—靶向数据生产—质量控制—SFT—评测归因"的数据闭环，重点提升跨视频对比与推理能力，并通过自动化数据生产提高有效训练数据的供给效率。**

关键词的转变：

```text
原叙事：数据生产 Pipeline（我负责找视频、标注、质检、自动化）
新叙事：模型能力提升项目（数据生产是其中一环，Pipeline 只是实现手段）

因果关系从"我做了什么"变成"我为什么这么做"：
模型 Benchmark → 发现能力缺口 → Error Map → 定义数据缺口
→ Targeted Sourcing → 难度控制 → Quality Gate → Rollout / SFT
→ Benchmark → +2.8 / +0.5 / +2.3 → 发现真正瓶颈：Coverage
→ 下一轮继续扩充能力覆盖
```

### 三个核心 Objective（只有三个）

```text
O1：提升多视频理解能力
    核心指标：内部 161 题（覆盖子集 +2.8）+ 迁移看 ClawEval（+0.5）
    + 泛化看 WildClawBench（+2.3）

O2：提高有效训练数据供给效率
    Targeted sourcing + 自动 prompt/CoT + TOS 入库 + 去重 +
    Human-in-the-loop QC，把数据生产从纯人工向半自动 Pipeline 迁移

O3：建立 Benchmark → Data 的闭环
    把"模型错在哪里"转化为"下一轮数据应该生产什么"
```

### 我的角色（从交付方到链路主导者）

```text
不是"数据交付方"，而是"能力提升闭环的一线主导者"：
├── 能力维度与难度体系设计（把"什么是好数据"显式化）
├── 靶向寻源采集（capability-driven sourcing，非 keyword-based）
├── Training Signal Quality Gate（质检 = 训练风险拦截）
├── 模型诊断理解（Error Map → 数据缺口 → Rollout 行为约束）
├── 分层评测与收益归因（+2.8/+0.5/+2.3 的读法）
└── 评测反馈闭环（归因 → 策略反馈 → 单变量验证）
```

## 三、设计层（1）：L1/L2/L3 能力维度体系

多视频理解是 VLM 公认短板（Video-MME 等 benchmark 上前沿模型集体丢分的场景）。真正的模型问题不是笼统的"多视频是短板"，而是：

> **模型在跨视频"对应—比较—推理"上的能力不足，而现有数据生产又存在难度坍缩、覆盖不足和证据结构不稳定的问题。**

能力维度按复杂度递进分三层：

```text
L1 跨视频感知（基础层，信息提取即可）
├── 空间方位 / 计数统计 / 事件定位 / 行为理解
├── 问题形态：单个视频内就能回答，但需跨视频采集样本
└── 例：两个视频里各有什么物体？两个场景的方位关系？

L2 跨视频对比（对应层，需建立跨视频对应关系）
├── 过程错误检测 / 时间交叉引用 / 实体匹配·状态差异 /
│   模式对比 / 功能步骤对齐
├── 问题形态：必须在 ≥2 个视频之间建立"对应关系"才能回答
├── 本质：跨视频实体/状态/时间对齐
└── 例：左视频里球是红的，右视频里变成蓝的了吗？

L3 跨视频推理（融合层，多源证据融合后推理）
├── 因果推理 / 假设·操作迁移 / 综合理解
├── 问题形态：跨视频证据融合后做因果/迁移/综合判断
├── 本质：多源证据 → 推理 → 结论
└── 例：A 视频的步骤在 B 视频的场景下会产生什么结果？

暂不做：叙事理解 / 时序排列（边界判断依据见第十二节）
```

**分层逻辑**："感知 → 对比 → 推理"的复杂度递进，与人类视觉认知的复杂度递进一致，也与模型能力评测的难度分层一致（能力评测需要难度梯度）。这个体系同时是**出题难度依据**和**评测难度天然分层**的来源。

### 可配对视频 —— 多视频数据采集的核心约束

```text
定义：能构建多视频问答的视频组合
├── 同实体不同状态（同一物体/场景的两个时刻）
├── 同过程不同视角（同一事件的两个拍摄角度）
├── 同场景不同时间（白天 vs 夜晚）
└── 同任务不同做法（做菜步骤 A vs 步骤 B，用于步骤对齐/错误检测）

为什么是核心约束：
├── 多视频理解的本质 = 跨视频对应关系的建立
├── 没有可配对性 → L2/L3 维度无从构造
└── 选材标准从"单个好视频"变成"成对的好视频"
    —— 多视频数据的核心不是"视频好不好"，而是"有没有形成
       有效的 cross-video relation"
```

## 四、设计层（2）：Ability × Difficulty 数据坐标系

这是本项目对"数据 Schema"最大的改造：数据不应该只有 `video / question / answer / cot`，而应显式携带**能力维度 × 难度维度 × 数据属性 × 训练属性**，让每一条数据变成"一条可归因的训练信号"。

```text
sample_id

能力维度
├── L1 / L2 / L3
├── spatial / counting / temporal
├── entity_matching / state_change
└── causal / transfer

难度维度（← 难度坍缩 Difficulty Collapse 的治理抓手）
├── video_duration        视频时长
├── information_density    信息密度
├── distractor_level       干扰信息量
├── number_of_entities     实体数量
├── cross_video_dependency 跨视频依赖程度
├── reasoning_steps        推理步数
└── evidence_span          证据跨度

数据属性
├── source / video_type / paired_video
├── source_quality / annotation_quality
└── synthetic / real

训练属性
├── dataset_version / sampling_weight
├── SFT / pretrain
└── target_skill
```

于是每个样本不再是"一个视频问答"，而是：

> **"针对 L2-实体状态差异、复杂度 4、双视频、跨时间证据的一条训练信号。"**

这样后面的采集、QC、主动学习、数据配比、Benchmark、badcase 才能真正连成闭环。**能力覆盖 × 难度覆盖 × 证据质量**构成训练数据的三维评价框架。

## 五、执行层（1）：Targeted Data Acquisition（能力驱动寻源）

面试中不要讲"我负责找视频"，要讲：**我把传统的 keyword-based sourcing 改成 capability-driven sourcing。**

```text
Benchmark 弱项 → 能力维度 → 数据缺口 → 检索策略
→ 视频候选 → 配对关系 → 难度验收

例：
L2 / 状态差异 → 寻找"同一实体不同状态"的视频对
L2 / 步骤对齐 → 寻找"同一任务不同操作路径"的视频对
L3 / 迁移     → 寻找"相似任务、不同环境"的视频对
```

### 寻源采集工作流（考点先行）

核心思路：**先看每道题本质在考什么，再据此设计检索逻辑寻源，最后用切/拼/合成把难度对齐示例。**

```text
需求：VLM 数据质检与重标
    ↓
锁定示例标尺（示例题目定义了目标难度 = 采集的对齐基准）
    ↓
按题型选择 pipeline（判断这道题本质考什么能力 → 走哪条寻源线）
    ↓
┌────────── 分题型寻源 + 机标（四条并行 pipeline）──────────┐
│ 题型（本质考点）        寻源 + 机标策略      检索逻辑要点   │
│ ① 视频细粒度理解   → 事件级寻源 + 机标   按事件/动作精确检索│
│ ② 双语 OCR        → 字幕与画面 OCR 机标 找带字幕/画面文字  │
│ ③ 考据检索/文本核查 → 检索与脚本构造机标 找可核查事实的视频 │
│ ④ 工程脚本        → 脚本化构造机标      脚本构造符合考点素材│
└──────────────────────────────────────────────────────────┘
    ↓
机标候选：素材 + 题目 + 草稿答案
    ↓
难度是否对齐示例？（对齐基准 = 锁定的示例标尺）
├── 对齐  → 写回作业表，三件套（素材 + query + answer）齐套 → 交付
└── 不对齐 → 换源 / 改题 / 重标 → 回到"机标候选"重新判定（闭环）
```

**关键设计决策**：

```text
① 考点先行：先判断"这道题本质考什么能力"，再设计检索逻辑，
   避免"找到视频再硬凑题目"。
② 寻源为主，构造为辅：主思路从 YouTube / B 站等平台寻源；
   个别题目找不到合适素材时，才用切 / 拼 / 合成补齐。
③ 难度对齐是采集的验收关：切/拼/合成的目的不是"造视频"，
   而是把素材难度做到和示例对齐（难度坍缩的源头治理）。
④ 机标 + 人工闭环：机标产出草稿三件套，难度不对齐则换源/改题/重标。
```

## 六、执行层（2）：Training Signal Quality Gate

不要讲"我做了质检"，要讲：**我建立的是 Training Signal Quality Gate——每一个 QC 维度都对应一个具体训练风险。**

| QC 维度 | 拦住的训练风险 |
|---------|----------------|
| 内容准确 | Label Noise（错误 response 每个 token 都产生错误梯度，SFT 对标签噪声几乎零容忍） |
| 回答完整 / 不可跳步 | Reasoning Path 缺失（答案对但跳步 = 把"跳步路径"当正确示范教给模型） |
| 格式一致 | Output Distribution Drift（结构不一致 = 稀释目标输出格式的概率质量） |
| 视频匹配 | Language Shortcut（不看视频也能答 = 教模型绕过视觉编码器、靠语言先验作答） |
| 难度对齐 | Supervision Strength 不足（难度坍缩 = 静默的信号强度损失） |
| 能力匹配 | Wrong Skill Supervision（训了目标之外的能力，配方失真） |

**这比"质检 400 条视频"高级很多**——质检不是交付前的形式审查，每一维都是一个训练风险的拦截器。

### 核心洞察：难度坍缩（Difficulty Collapse）

> **数据正确 ≠ 训练信号正确。** 这是本项目最值得保留的一线洞察。

```text
定义：标注数据的实际难度 < 示例题目定义的目标难度，
     导致模型训练时学到的能力低于预期。

机制：示例题目 = 难度基准 → 标注者"顺手简化" → 数据难度整体
     偏离目标 → 模型只在简化分布上训练 → 真实复杂度一来就失效
```

两个第一手翻车案例：

```text
案例 A：空间复杂度坍缩
├── 示例素材：真实复杂地铁线路图（多线路、高噪声）
├── 实际标注：极简交叉线路图
├── 后果：模型只学到"看到两条线交叉"，没学到
│         "在大量干扰信息中识别目标空间关系"
└── 本质：噪音量（干扰信息）是难度的一部分，被悄悄删掉了

案例 B：时间复杂度坍缩
├── 示例素材：1 小时长视频
├── 实际标注：10 秒短视频
├── 后果：长视频"跨时间信息检索与整合"信号完全缺失
└── 本质：时长 = 难度维度，被压缩（后已补充修正）
```

为什么比错标更有害：**难度坍缩是静默的质量损失**——错标能被发现，难度坍缩数据"看起来都对"，不易被发现，却让模型能力天花板悄悄降低。修复方式：把"难度对齐"从质检打回**前移到采集验收**（第五节的难度验收关），并进入质检标准（复杂度/时长/噪音量对齐）。

### 多视频 CoT 证据结构

多视频 CoT 与单视频 CoT 的本质区别：必须显式声明"证据来自哪个视频"。

```text
标准结构（逐视频、逐证据段落 + 汇总结论）：
├── 段落 1：视频 A 证据（时间点 + 画面内容 + 观察结论）
├── 段落 2：视频 B 证据（同上）
├── 段落 3：对应关系（A 的 X 与 B 的 Y 之间存在什么关系）
└── 汇总结论：基于证据的回答

目的：证据可追溯 → 模型学会"引用"而非"编造"
与 Learnability 的连接：教的是"证据组织框架"（先定位、再比较、
后结论），而非"这道题的答案"——新场景能复用同一框架。
```

### 交付格式与数据治理

```text
为什么用 video_tos_link 而非网络 URL：
├── 网络 URL：可能失效、无权限控制、无法统一治理
└── TOS（对象存储）：持久化、权限可控、入库后可去重/质检

为什么 sample_id 在首位：数据治理的锚点，支持问题追踪与
```

## 七、消费层（1）：坐标系与靶向 SFT 定位

视频进入 VLM 的固定链路：mp4 抽帧（帧数 = token 预算与信息保留的权衡）→ 每帧经视觉编码器（ViT，切 patch + 高分辨率窗口注意力）编码为视觉 token → 帧间用时序注意力与时序位置编码对齐（Qwen2.5-VL 一类把位置编码与绝对时间对齐）→ 视觉 token 与文本 prompt token 拼接 → LLM 解码器自回归生成 response。

后训练三范式定位（本轮明确止于 SFT）：

| 范式 | 数据形态 | 学习方式 |
|------|----------|----------|
| SFT | 正样本 | 离线模仿学习 |
| DPO | 成对偏好数据 | 直接优化相对概率 |
| RL（PPO/GRPO） | prompt + 奖励 | 在线采样轨迹，用奖励更新策略 |

三步流程 = **靶向 SFT（targeted SFT）**，不是 RL：

```text
① 模型轨迹对比（诊断"模型错在哪"）
② 行为引导 Rollout（造"高质量正样本"）
③ SFT 监督微调（模仿正样本，完成分布对齐）
本轮算法侧明确止于 SFT，不涉及 RL 参数更新。
```

三元组 `(视频, prompt, response)` 在训练管线中三部分命运不同：

| 组成 | 进入模型后的形态 | 训练时的角色 |
|------|------------------|--------------|
| video | 抽帧 → ViT 编码为视觉 token，带时序位置编码 | 输入条件，loss 掩码 |
| prompt | 分词为文本 token，套 chat template | 输入条件，loss 掩码 |
| response | 分词为文本 token，接在视觉与 prompt 之后 | 唯一计算 loss 的监督目标 |

这批数据的关键属性是"**同类别属性**"：视频对准已有 VQA 例题的题型类别定向采集，覆盖内部 161 题中的 72 题——相当于把训练数据当"错题本"投放，模型在哪类题弱就补哪类题，而非均匀铺量。

## 八、消费层（2）：模型诊断 —— Base Model Error Mapping

在用数据微调前，先拿 base 模型对全部已标注 prompt 跑推理，保存完整轨迹（含 CoT），与人工 response 逐条对比。**这一步不更新任何参数，产出物是一张"错误地图"。**

```text
Base VLM → 对 161 题 / 全量 prompt 推理 → 与 Ground Truth 对比
   ↓
① 可复现推理：固定解码配置（低温/贪心），输出完整 CoT
② 两层对比：
   ├── 结果层：判最终答案对错（答案抽取 + 规则/judge 判定）
   └── 过程层：对齐推理链，定位偏离发生在第几步
③ 错误归类聚合 → Error Taxonomy：

Temporal Error   ├ 漏看关键时间段 ├ 时间顺序颠倒 └ 跨视频时间对应失败
Perception Error ├ object miss   ├ state miss   └ relationship miss
Reasoning Error  ├ skipped step  ├ causal error └ transfer failure
```

错误地图决定两件事：**数据补在哪里**（本轮 72 题优先对准薄弱题型）和 **Rollout 要规范什么行为**（比如发现模型普遍跳过时序推理，就在行为引导里强制"先陈述关键帧观察、再推理"）。

**为什么这步不可省 + 为什么不是"直接多标一点数据"**：SFT 是 off-policy 模仿学习，只给正样本，模型不知道自己错在哪。轨迹对比把当前策略 π_θ 与目标分布的 gap 显式定位出来。而诊断之后会发现**不是所有数据价值相同**，于是走的是 Targeted Data Strategy（错误地图 → 数据缺口 → 定向采集/构造），而不是 Scale Data Strategy。

> 💭 猜测：以上为结合算法反馈的机制还原，具体对比脚本、错误归类口径以算法侧实现为准。

## 九、消费层（3）：行为引导 Rollout + SFT

### Rollout = 高价值监督信号生成器（拒绝采样，不是 RL）

不要说成"我们用了 RL"。本项目 rollout 的产物最终进了 SFT 训练集，工程实质是**引导式数据合成**——业界称拒绝采样（rejection sampling）或 STaR 式自我改进。

```text
Problem Prompt → Behavior Instruction → Model Sampling
→ N Candidate Responses → Answer Correct? → Reasoning Correct?
→ Format Correct? → Accept / Reject → SFT Dataset

① 行为注入：system prompt / few-shot 规定 response 行为模式
   （先陈述关键帧观察→时序/因果推理→结论；字段与格式固定）
② 采样：教师模型或当前模型在 temperature > 0 下多条采样
③ 筛选（拒绝采样）：只留"答案正确 且 过程合规"的轨迹；
   答案对但路径错的丢弃（过程监督，非只看结果）
④ 混入训练集：入选轨迹 + 人工三元组 = SFT 正样本
```

意义：**把模型"已经会答但不会正确解释"的轨迹，转换成可学习的正向行为样本。** 这与 CoT 质检高度统一——response 要求"压缩充分精简、不可跳步、因果明确"，正是 rollout 的筛选条件。

后训练范式谱系（严格区分）：

| 方法 | 数据需求 | 在线采样 | 优化目标 |
|------|----------|----------|----------|
| SFT | 正样本 response | 否 | 最大化 gold response 似然 |
| RLHF/PPO | prompt + 奖励模型 | 是 | 最大化 RM 奖励，KL 约束防跑偏 |
| DPO | 偏好对 (chosen, rejected) | 否 | 直接拉大 chosen 与 rejected 的相对概率 |
| GRPO | prompt + 可验证奖励 | 是（同题 G 条） | 组内奖励归一化为 advantage，PPO 式 clip 更新 |

**为什么止步于 Rollout + SFT 而不上 RL**：开放型视频 VQA 没有廉价可验证的奖励（答案对错要 judge/人工判定，成本高）；且 RL 普遍需要 SFT 冷启动。业界主流 VLM recipe（Qwen2.5-VL、Seed-VL）同样是 SFT 阶段用拒绝采样、RL 阶段才上可验证奖励。

> 💭 猜测：采样条数、筛选阈值、教师模型选择等具体配置以算法侧实验为准。

### SFT 监督微调：训练目标与损失

给定视觉 token v 和 prompt x，让模型对人工 response y 的条件概率最大化。损失是 response token 上的平均负对数似然：

$$\mathcal{L}_{SFT}=-\frac{1}{|y|}\sum_{t=1}^{|y|}\log p_\theta(y_t\mid v,x,y_{<t})$$

```text
关键细节：
├── loss mask：视觉 token v 与 prompt x 只作为条件，梯度只从
│   response token 回传（模型不需要学"生成视频/生成问题"）
├── 视觉编码器通常冻结或用显著更小的学习率，主训 LLM（全参/LoRA）
├── chat template 训练与推理严格一致
├── epoch 1–2（小数据多轮必过拟合）
└── 按比例混通用指令数据，防灾难性遗忘（垂类降智）

CoT 为什么能被学会：teacher forcing 下每个推理步 token 都被要求
"基于观察 + 已有推理"预测下一步，正确路径整条序列概率被反复抬高；
rollout 筛选又保证被模仿的路径本身是对的。学到的是
p(下一步推理 | 观察, 已有推理) 的行为分布，而非某个答案。

SFT 的边界：只抬高正样本似然，不显式压低坏样本——不教"好答案
好在哪"（那是 DPO/RL 的工作）。因此正样本质量（质检 + rollout
筛选）直接决定 SFT 天花板。这就是"质检标准 = SFT 天花板"的算法版表述。
```

## 十、消费层（4）：分层对照评测与收益归因

### 两轮对照评测

标准 before/after 对照：第一轮用未微调的 base 模型，第二轮用 SFT 后模型；两轮在完全相同的 benchmark 上、按完全相同 rubric 打分，作差得 delta。**唯一变量是模型权重。**

| 维度 | 第一轮（基线） | 第二轮（SFT 后） |
|------|----------------|------------------|
| 模型 | 初始 base，未经本轮微调 | 人工三元组 + rollout 入选轨迹 SFT 后 |
| 评测集 | 内部 161 题 / ClawEval / WildClawBench | 与第一轮完全相同 |
| 推理配置 | 固定解码（温度、抽帧、prompt 模板） | 与第一轮严格一致 |
| 打分 | 统一 rubric | 同一 rubric、同一 judge 版本 |

**第一轮推理一步两用**：base 模型在 benchmark 上的推理，一方面产出基线分数，另一方面就是第八节"模型轨迹对比"的输入——同一批错误 case 既算基线、又当训练靶点。这也是轨迹对比必须在 SFT 前完成的原因。

**rubric 打分**：视频 VQA 多为开放作答，不用精确匹配。按 rubric 打分维度：最终答案是否正确、关键画面与时序是否覆盖、因果推理是否成立、格式是否合规。工程实现 = 答案抽取 + 规则校验 + judge 模型评分。两轮必须锁死同一 rubric + 同一 judge 版本，否则 delta 不可比。

### 三套 benchmark 各回答什么（相互独立，别混口径）

> ⚠️ 关键更正：`72/161` 覆盖率与 `+2.8` 覆盖子集**属于内部 161 题集**，与 ClawEval 无关。ClawEval / WildClawBench 是两套**独立的公开 Agent 基准**，各自出 `+0.5` / `+2.3`。此前版本把 ClawEval 当成"内部 161 题 VQA 集"是口径错误，现更正。

| Benchmark | 身份 / 构成 | 作用与结果 |
|-----------|-------------|-----------|
| 内部 161 题 | 自建（其实就是"这 161 道题"，不一定是正式命名 benchmark），靶向数据覆盖其中 72 题 | 覆盖子集 **+2.8**；未覆盖 89 题充当降智监控（不应显著下滑）；覆盖率约 45% |
| ClawEval | 公开"LLM as agents"评测 harness（General / Multimodal / Multi-turn 三 split，Video QA 只在 Multimodal） | 全量 **+0.5**——衡量能力向通用 / 多模态 Agent 任务的迁移 |
| WildClawBench | 公开真实世界长链路 Agent 基准（OpenClaw 环境，单任务 10~60+ 次工具调用） | **+2.3**——衡量向真实世界 Agent 任务的进一步泛化 |

**防数据泄漏是归因成立的前提**：SFT 用的是同类别属性的新采集视频，与三套 benchmark 严格不重叠，WildClawBench 完全 held-out。

### 三个数字的归因

| 评测项 | 口径 | 提升 | 怎么读 |
|--------|------|------|--------|
| 内部 72 题子集 | 内部 161 题中被训练数据直接覆盖的题 | **+2.8** | 靶向数据直接效果，方向有效的硬证据 |
| ClawEval 全量 | 公开通用 / 多模态 Agent 基准 | **+0.5** | 大量与视频目标无关的任务（finance/communication 等）稀释后的均值 |
| WildClawBench | 公开真实世界长链路 Agent 基准 | **+2.3** | 同类能力在未见真实任务上的泛化收益 |

```text
├── +2.8（内部覆盖子集）：数据直接覆盖的题型提升最大，证明三元组
│   形态、质检口径和训练链路本身有效。
│   → Targeted Data → Capability Gain 的直接因果证据。
├── +0.5（ClawEval 全量）：ClawEval 是通用 Agent 基准，大部分任务
│   （finance/communication/productivity 等）与多视频能力无关、
│   分数基本不动，把真正相关的 Multimodal / Video QA 收益拉低到
│   全量均值。→ 低不代表数据没用，而是"用错基准看收益"+"相关子集
│   被无关任务稀释"，应下钻到 Multimodal / Video QA 子项。
└── +2.3（WildClawBench）：最值得注意——训练用的是同类别新视频而非
    评测原题，模型无法靠背答案获益；它衡量真实世界长链路任务，
    收益说明学到的解题路径能迁移到未见的真实任务。
    → 行为引导 Rollout 规范出的是可迁移的行为模式，不是记忆。
    ⚠️ 但归因未隔离：+0.5 / +2.3 是 Agent 基准，共享 base model 上
       还并行训练着 vlm-agent 数据线（10.11），这两个数字是"理解迁移
       ＋Agent 数据直训"两条来源共同作用的结果，不能干净地全部记在
       多视频 VQA 头上。迁移机制见 10.10，隔离方法见 10.10 末尾消融。
```

**反直觉结论（应保留）**：首轮实验最大的发现不是"我们的数据有效"，而是"**数据有效，但覆盖不足**"。内部集覆盖子集 +2.8 证明方向有效，而全量收益受覆盖率限制——下一轮该做的不是无脑提高单条数据质量，而是扩大真正命中模型弱项的题型覆盖。这就把项目从"数据交付"升级成"实验 → 结论 → 资源重新分配 → 下一轮实验"的 Data Strategy。

> 📌 待确认：内部 161 题的能力标签口径、`+2.8` 的具体统计方式（覆盖子集内 pre/post 均值差）、以及 ClawEval / WildClawBench 各 split 与 Video QA 子项的拆分数字，以算法侧评测配置为准。

### 10.5 更深一层：指标 → 能力的映射缺口（当前叙事最大的短板）

> 核心判断——**当前叙事最大的问题不是"指标不够"，而是"指标 → 能力"的映射没建立起来。**

```text
现状：+0.5 / +2.3 只能告诉读者"模型整体变好了"，
     无法回答"到底是哪一种 VLM 能力变好了"——
     是跨视频感知、跨视频对齐、时序理解、长视频理解，
     还是 Agent 的工具调用能力？

后果：能证明"模型整体能力发生了变化"，
     不能证明"我构建的 L1/L2/L3 多视频能力发生了变化"。
     ——这正是"不知道到底提升了什么"的根本原因。

缺的那一层 = 能力归因层：
Benchmark Question → Capability Label → Training Data Coverage
→ Pre/Post Accuracy（→ 覆盖能力题 vs 未覆盖能力题的分别 Δ）
```

```text
│   ├── Multimodal 101：网页生成 / Video QA / 文档理解
│   └── Multi-turn 38：多轮交互 / 澄清 / 建议
├── 能力口径：Completion（完成）/ Safety（安全）/ Robustness（稳定）
└── 结论：ClawEval +0.5 ≠ VLM 视频理解 +0.5，
    它代表"通用 / 多模态 Agent 任务完成能力"；只有 Multimodal split
    里的 Video QA 与本项目直接相关。

WildClawBench（InternLM/WildClawBench）：
├── 定位：real-world, long-horizon agent evaluation（OpenClaw 环境）
├── 任务例：足球视频剪精彩片段 / 多轮邮件协商 / 搜索结果找矛盾 /
│   无文档代码库写推理脚本 / 隐私泄漏检查（单任务 10~60+ 次工具调用）
└── 衡量的是"真实环境下长链路、多步骤、自主任务执行的 Agentic 能力"，
    不是单纯"你看懂这个视频了吗"。

三套基准的正确定位（不要都说成"衡量多视频能力"）：
├── 内部 161 题：衡量目标多视频能力本身
├── ClawEval：衡量能力向通用 Multimodal Agent 任务的迁移
└── WildClawBench：衡量能力向真实世界长链路 Agent 任务的进一步泛化
```

### 10.8 "72 / 161" 需要重新解释（且别和 ClawEval +0.5 混）

```text

     好像 +0.5 是 161 题被稀释的结果——错。+0.5 是另一套公开基准。
     内部 161 题自己也有一个"全量均值 Δ"（覆盖子集 +2.8 被 89 题稀释后），
     那才是和 72/161 直接相关的数字。

72/161=45% 只能说明"45% 的内部 benchmark case 有对应训练数据"，
     不能直接推出"剩下 55% 没覆盖所以内部全量只小涨"——中间缺
     "能力标签 + 覆盖 → Pre/Post 分别 Δ"的证据链。

要补的证据链（只在内部 161 题上做）：

得到：覆盖能力的题 +2.8 vs 未覆盖能力的题 +0.x
才真正证明：数据覆盖 → 能力提升 → 内部全量收益被覆盖率限制。
（ClawEval / WildClawBench 是独立的迁移 / 泛化验证，别混进这条链）
```

### 10.9 数据质量 Gate → 能力覆盖矩阵（把三维评价升级为决策表）

把第四节的"能力覆盖 × 难度覆盖 × 证据质量"进一步落成一张带收益的决策矩阵（数字为示例）：

```text
| 能力       | 数据覆盖 | 难度 | 证据质量 | SFT收益 | OOD收益 |
| L1 跨视频感知 | 80%   | 高  | 95%   | +13   | +4    |
| L2 跨视频对比 | 65%   | 高  | 93%   | +13   | +5    |
| L3 跨视频推理 | 45%   | 中高 | 91%   | +10   | +3    |
| 长视频理解    | 30%   | 高  | 90%   | +4    | +2    |
| 时序推理     | 40%   | 高  | 92%   | +8    | +3    |

据此做资源分配（不是所有数据都值得继续扩）：
├── L1 覆盖 80% / 收益 +13 → 已较充分，不必再扩
├── L2 覆盖 65% / 收益 +13 → 高价值，继续扩
├── L3 覆盖 45% / 收益 +10 → 高价值，重点扩
└── 长视频 覆盖 30% / 收益 +4 → 收益低，可能要重新设计数据难度/质量
→ 从"普通数据生产项目"升级为 Benchmark-driven Data Engine。
```

**这一层补上后，项目叙事从**"我做了很多数据，模型涨了几个点"**升级为**"我发现模型在 L2/L3 跨视频对齐与推理上有明确缺口 → 构建对应难度数据 → SFT 后 L2 +X、L3 +Y → 未见数据上仍 +Z → 通用 Multimodal / Agent 基准上进一步 +X → 证明学到的是可迁移能力而非记忆 benchmark"。

### 10.10 定位澄清：交付 VQA，为什么能在 Agent 基准上涨分？

> 这是本项目最容易被面试官追问、也最容易被自己讲错的一环。核心答案一句话：**这是能力迁移（capability transfer），不是"我训练了 Agent 能力"。**

```text
自建 VQA 数据 → SFT 教给模型的是"感知 + 跨视频推理"这类底层子能力
        ↓
Agent 任务（WildClaw：剪足球视频精彩片段 / 从搜索结果找矛盾 / …）
里内含一步"看懂这段视频 / 从视觉内容抽取信息"
        ↓
若该视觉子步骤原本是瓶颈 → 底层理解变强 → 这一步做对
        ↓
依赖该步骤的 Agent 任务端到端完成度上升（benchmark 涨分）
```

两个关键限定（正好解释了 Agent 基准为什么只涨一点）：

```text
① 不是训练了 Agent 行为本身（planning / tool orchestration 基本不变）
   → 所以增益只出现在"吃视觉"的任务上，不吃视觉的任务分数不动。
② 只有视觉步骤在关键路径上时才有迁移增益
   → ClawEval 的 finance / communication 任务根本不吃视觉，
     把相关子项（Multimodal / Video QA）的收益稀释到 Overall +0.5。
```

**为什么这个定位是合理的、不是牵强附会**：底层视觉理解是多模态 Agent 的"感官"，感官变准，下游依赖它的决策自然更可能正确——这与"视力矫正后，需要读仪表盘的工作出错率下降"是同一类因果。本项目正是用视觉理解数据去补 Agent 的"感官"瓶颈，不直接训练规划/工具调用等 Agent 行为。

**归因的诚实边界（务必保留，否则一追就穿）**：

```text
现实：共享 base model 上并行训练着多条数据线——本项目的视觉理解数据，
     与另一个独立项目"长视频复杂推理"的数据（`bytedance-长视频复杂推理能力建设.md`）。
后果：WildClaw +2.3 / ClawEval +0.5 是端到端 Agent 分数，无法干净地
     全部归因给本项目的视觉理解数据，需与并行数据线做隔离。
证明方法（消融，尚未做）：
├── 只加本项目视觉理解数据 → 看 Agent 基准 Δ = 本项目净贡献
├── 只加长视频复杂推理数据 → 看 Agent 基准 Δ = 该项目净贡献
└── 两者都加 → 看是否 ≈ 两者之和（判断有无协同 / 冗余）
在消融数据出来前，对 Agent 基准的表述保持"端到端收益（多数据线共同作用、
归因未隔离）"，不写成"本项目视觉数据独立带来了 +2.3"。
```

### 10.11 与并行项目"长视频复杂推理"的边界

> 说明（2026-09-08）：本项目（vlm-agent，以视觉理解为杠杆）与另一个独立项目"长视频复杂推理"（见 [bytedance-长视频复杂推理能力建设.md](./bytedance-长视频复杂推理能力建设.md)）共享同一套"能力诊断 → 靶向数据 → 质检 → SFT → 评测归因"方法论，且都会产出视频类训练数据、在共享 base model 上训练，因此二者的 Agent 基准收益需要消融隔离（见 10.10）。本节给出边界对照，避免把两者混为一谈。

```text
两个并行项目的分工（同方法论，侧重不同）：
┌─────────────┬──────────────────────────┬──────────────────────────┐
│ 维度        │ vlm-agent（本文，视觉杠杆）│ 长视频复杂推理（独立项目）│
├─────────────┼──────────────────────────┼──────────────────────────┤
│ 出发点      │ Agent 基准失分 → 补视觉瓶颈│ 长视频信息获取/推理能力  │
│ 目标基准    │ ClawEval / WildClaw（端到端）│ 长视频专项评测（分桶）  │
│ 能力体系    │ L1/L2/L3 跨片段感知—对比—推理（服务 Agent 视觉子步骤）│ 身份/OCR/排序/多跳等长视频能力地图 │
│ 数据形态    │ 视频三元组 (Q/A/CoT)     │ 视频三元组 (Q/A/CoT)     │
└─────────────┴──────────────────────────┴──────────────────────────┘

一句话：本项目从"Agent 基准为什么失分"出发，把视觉理解当作抬升 Agent 分数
的杠杆；长视频复杂推理从"长视频能力地图"出发，目标是长视频专项能力本身。
两者数据形态相近、可能共享部分素材，所以 Agent 基准收益必须靠 10.10 的消融拆分。
```

## 十一、闭环层：评测反馈 → 数据策略（工作工具）

> 把"交付即结束"升级为 **评测 → 归因 → 策略反馈 → 迭代验证** 闭环。
> 使用节奏：每轮交付后 1-2 天完成归因，周内发出策略反馈。

### 四类根因分类框架（归因第一步：分类，不做个案分析）

```text
① 任务定义问题（标准文档有歧义 / 任务本身难界定）
   判定线索：同一 prompt 多人判分分散、某能力维度整体失败率异常
   归因动作：回到标准文档查 5 部件（任务对象/证据边界/输出格式/
             容错规则/排除项）哪部分模糊
   策略方向：修订标准 / 补充示例 / prompt 模板调整

② 数据源问题（素材不足 / 质量差）
   判定线索：某能力维度成批失败、可配对视频稀缺、素材不达标
   归因动作：查采集关键词覆盖度矩阵、可配对率统计
   策略方向：补关键词 / 换数据源 / 调整配比

③ 标注执行问题（人员理解偏差 / 漏标 / 错标）
   判定线索：个案失败、同类问题集中在少数标注者、格式错误
   归因动作：对照标注指引，定位示例/培训缺口
   策略方向：补标注指引示例 / 定向培训 / 质检前置

④ 评测规范问题（容差设计不合理 / 判分规则误伤）
   判定线索：某类答案系统性判错、容差边界附近大量失败
   归因动作：检查判分五模式（规则/容差/部分分/相似度/LLM fallback）
   策略方向：调整容差 / 修正判分代码 / 增加排除项
```

### 闭环验证原则

```text
├── 单变量：一轮只改一个主变量，保证可归因
├── 同评测集：新旧对比用同一套判分规范，不跨版本比分数
└── 区分"数据问题 vs 评测问题"：先查评测规范误伤，再归因数据

与 SFT 归因的同构性：CoT 评估失败分布 → 修生成 prompt；
采集失败分布 → 修关键词策略；模型 badcase → 修数据策略。
同一套「归因 → 迭代」闭环贯穿全链路。
```

### 数据策略反馈报告（给算法/研发，一页纸）

```text
## 本轮概况：交付 N 条，合格率 X%（较上轮 ±X pp），失败主要分布…
## 根因与建议（按影响排序，最多 3 条）
   根因 A（任务定义，占失败 40%）→ 现象 + 建议 + 预期影响
   根因 B（数据源，占失败 25%）→ 建议
   根因 C（标注执行，占失败 15%）→ 建议
## 下轮计划：只调 1 个主变量，其余保持不动
## 需要算法侧配合：复测结果回传 + 哪些 bad case 被修复
```

## 十二、自动化 Pipeline（第二主线：把靶向数据策略产品化）

不是"我写了一个爬虫"，而是**把"人工寻源 → 手工出题 → 手工写 CoT → 手工填表"的数据生产过程拆成可自动化 DAG，并保留人工作为最终质量 Gate。**

```text
关键词爬取 → TOS 入库 → 去重 → 自动生成 Prompt → 自动生成初版 CoT
→ 飞书作业表自动填写 → 人工终审 → 交付
```

### 为什么不 100% 自动（Human-in-the-loop boundary）

```text
├── 自动生成 Prompt 容易语义漂移
├── CoT 正确 ≠ CoT 可学习
├── 多视频题要求跨视频证据对应
└── 难度对齐很难靠单模型 confidence 判断

所以：自动化初版 + 人工终版 = 合理的人机分工边界
（机器负责高吞吐候选生成与预处理，人工保留终审与高风险兜底）
```

### 自动生成 CoT 的质量闭环（三层 Grader）

自动生成初版 CoT 有三大风险：结构不合规、证据虚构（LLM 幻觉）、答案错误。没有评估 → 错误直接流到人工终审 → "自动化"反而引入新质量风险。

```text
Grader 1 规则/代码（零成本，全量跑）
├── JSON schema 校验 + CoT 段落结构检查（逐视频标记）
├── answer 格式检查 → 输出 pass/fail（fail 标记原因）

Grader 2 LLM 评分器（LLM-as-Judge，全量或抽样）
├── D2 证据真实性：抽取 CoT 证据声明，对照视频帧验证
├── D3 证据对应性：L2/L3 跨视频关系是否被正确建立
└── 注意：评测模型与生成模型分离（避免自评偏差）

Grader 3 人工抽检（权威层，如 10%）
└── 校准 Grader 2 阈值 + 建立人工通过率基线

核心指标：初版 CoT 通过率 / 各维度失败分布 / 人工通过率
校准指标：LLM vs 人工一致率 / 误杀率 / 漏放率
迭代闭环：失败案例归因 → 修生成 prompt（证据虚构高发 → 加约束
"只引用画面实际出现的内容"；结构不合规 → few-shot 强化）
```

### 采集环节评测：覆盖度与多样性（补齐评测链最后一块拼图）

评测链三环节（采集 → 质检 → 应用）中，采集是唯一缺评测的环节。它评的是**批次/集合的分布**（确定性低，需抽样 + 统计推断），而非单条数据（确定性高，规则可全量自动化）。

```text
M1 覆盖度矩阵：类型(L1/L2/L3) × 场景 × 关键词 → 目标量 vs 实际量
   → 缺哪个格子补哪个关键词（评测驱动采集）
M2 可配对率：抽样标注"是否可配对"（L2/L3 样本可构造性的量化）
M3 去重有效量：去重后有效样本 / 原始采集量（采集冗余度）
M4 类型准确率：抽样标注"是否真是目标类型"（关键词召回质量）

归因 → 动作：
├── M1 某格缺口大 → 该类型×场景新增关键词
├── M2 配对率低 → 关键词从"搜单个视频"转向"搜配对组合"
├── M3 冗余率高 → 去重前置到爬取环节
└── M4 类型准确率低 → 换关键词或加负例过滤规则
```

### Data Efficiency（比"生产了多少条"更重要的指标）

$$DataEfficiency=\frac{\Delta Benchmark}{Effective\ Training\ Samples}\qquad LabelEfficiency=\frac{\Delta Benchmark}{HumanHours}$$

内部 161 题只有约 45% 覆盖、覆盖子集就已 +2.8 —— 这直接说明：**数据的"能力命中率"比单纯数据规模重要**（少量高质量靶向数据 > 大量无策略数据）。

### 暂不做方向的评测边界判断

用三问前置判断一个能力方向做不做：

```text
① Grader 可设计性：正确答案能稳定判定吗？
② Trial 可构造性：能稳定获取这类数据吗（可配对视频可得？）
③ 价值优先级：是不是模型当前的能力瓶颈？

应用（为什么"叙事理解/时序排列"暂不做）：
├── Grader 可设计性 ❌：叙事好不好主观性强，GT 难稳定判定
├── Trial 可构造性 ❌：需长视频 + 完整叙事，可配对素材稀缺
└── 价值优先级 🟡：当前瓶颈在感知/对比/推理，叙事非最高优先级
三问两问不过 → "暂不做"是评测可行性驱动的决策，不是随意取舍。
```

## 十三、四视角展开

## 十四、面试故事

### 版本 A（30 秒）

> 我在字节参与的不是单纯的 VLM 视频数据生产，而是一个多视频理解能力提升项目：针对模型在跨视频对比、推理上的能力缺口，建立了"模型诊断 → 靶向数据 → 质量控制 → SFT → 评测归因"的数据闭环。我从考点先行的能力驱动寻源，到 Training Signal Quality Gate 质检，端到端负责约 400 条数据（74 topic，周交付）。结果用三套独立评测集验证：内部 161 题里靶向覆盖的子集 +2.8（方向有效的直接证据），公开真实世界 Agent 基准 WildClawBench +2.3（说明学到的是可迁移能力、不是背答案），公开通用 Agent 基准 ClawEval 全量 +0.5（大量与视频无关任务稀释后的均值，应看其 Multimodal/Video QA 子项）。首轮最大的结论是"数据有效但覆盖不足"——内部覆盖率仅约 45%，下一轮该扩覆盖而非继续提质。

## 十五、面试官追问准备

```text
Q1：为什么多视频理解比单视频难？
→ 跨视频对应关系的建立：单视频是时间线内推理，多视频要在不同
   视频间对齐实体/状态/时间，还要判断差异和因果。L2/L3 都依赖
   这种对应能力，是当前所有 VLM 的短板。

Q2：什么叫"数据正确≠训练信号正确"？
→ 难度坍缩。示例是复杂地铁图，标注只给极简交叉图；示例是 1h
   视频，实际只给 10s。数据"都对"但难度系统性偏离目标，模型
   学到的能力低于预期。难度是训练信号的一部分，比错标更隐蔽。

Q3：行为引导 Rollout 是 RL 吗？
→ 不是。产物进了 SFT 训练集，工程实质是拒绝采样/STaR 式数据合成，
   没有奖励信号驱动的参数更新。RL 的 rollout 是在线采样 + 奖励更新。

Q4：为什么不直接上 RL？
→ 开放 VQA 没有廉价可验证奖励（要 judge/人工，成本高），且 RL 需
   SFT 冷启动。业界主流 VLM recipe 也是 SFT 用拒绝采样、RL 才上
   可验证奖励。本轮数据规模下 rollout + SFT 性价比最高。

Q5：ClawEval 只有 +0.5 是不是说明数据没用？
→ 不是。首先要分清基准：+0.5 是**公开通用 Agent 基准 ClawEval** 的全量，
   它大部分任务（finance/communication/productivity）跟多视频能力无关，
   会把真正相关的 Multimodal/Video QA 收益稀释掉，应下钻子项看。真正
   证明数据有效的是**内部 161 题**的覆盖子集 +2.8。别把 ClawEval 的 +0.5
   当成"内部 161 题被 89 道未覆盖题稀释"的结果——那是两套独立的集。
   内部集自己的全量收益受覆盖率（约 45%）限制，那才是"数据有效但覆盖
   不足"的依据。

Q6：WildClaw 的 +2.3 怎么排除"背答案"？
→ 训练视频与 WildClaw 严格隔离（held-out），训练用的是同类别新
   视频而非评测原题，模型无法靠记忆获益，只能归因于解题路径的
   真实泛化。这比 +2.8 更有说服力。

Q7：loss mask 是什么？
→ 视频和问题是"给定输入"，模型不需要学"生成视频/问题"，梯度只从
   response token 回传，让模型专注学"给定视频和问题时怎么答"。

Q8：CoT 怎么被 SFT 学会？
→ teacher forcing 下每个推理步 token 都被要求"基于观察+已有推理"
   预测下一步，正确路径整条序列概率被反复抬高；rollout 筛选保证被
   模仿的路径本身是对的。学到的是 p(下一步推理|观察,已有推理)。

Q9：怎么找到可配对视频？
→ 同实体不同状态/同过程不同视角/同场景不同时间/同任务不同做法。
   关键词围绕"能形成对比/对应的组合"设计（如"同一道菜两种做法"），
   召回后人工抽检配对率（M2 指标）。

Q10：你的采集环节怎么保证质量？
→ 补了覆盖度评测（评测链最后一块拼图）：覆盖度矩阵/可配对率/去重
   有效量/类型准确率四指标，前两个统计指标全量自动，配对判定用
   LLM 预筛 + 人工抽样校准，结果回流到关键词策略。

Q11：视频去重怎么做？为什么比文本难？
→ 帧级/感知哈希识别不同编码但内容相同的视频。比文本 MinHash 难在
   "重复定义"模糊 + 计算成本高（解码、抽帧、特征提取）。

Q12：为什么用 video_tos_link 而不是网络 URL？
→ 网络 URL 会失效、无权限控制、无法统一治理；TOS 保证持久化、
   权限可控、可去重可质检，交付的是存储引用（sample_id 做锚点）。

Q13：这套流程和你的质检工作什么关系？
→ 质检标准就是 SFT 正样本的质量定义：准确性拦标签噪声、完整性拦
   过程缺陷、格式拦格式漂移、匹配度拦语言捷径、难度对齐拦监督强度
   不足。交付层和消费层是同一套语言。

Q14：+0.5 / +2.3 到底提升了哪种能力？（最容易被问倒，也最能体现深度）
→ 这正是当前叙事的最大短板：只有"指标"没有"指标 → 能力"映射。裸
   分数只能说明"模型整体变好"，证明不了"我构建的 L1/L2/L3 多视频能力
   变好"。要补一层能力归因：给 benchmark 每题打能力标签 → 按标签 ×
   数据覆盖分别算 Pre/Post Δ → 得到"覆盖能力题 +2.8 vs 未覆盖题 +0.x"，
   才能说清是跨视频对齐（L2）、关系推理（L3）在涨，而非工具调用在涨。

Q15：ClawEval / WildClaw 是视频理解基准吗？
→ 不是纯视频理解基准，而且和内部 161 题是**三套独立的集**。ClawEval 是
   公开"LLM as agents"评测 harness（General / Multimodal / Multi-turn 三
   split，Video QA 只在 Multimodal 里），WildClawBench 是公开真实世界长链路
   Agent 评测（单任务 10~60+ 次工具调用）。三套分层定位：内部 161 题衡量
   目标多视频能力本身（覆盖子集 +2.8、覆盖率 45%）、ClawEval 衡量向通用/
   多模态 Agent 任务的迁移（+0.5，应看 Multimodal/Video QA 子项）、
   WildClawBench 衡量向真实世界 Agent 任务的泛化（+2.3）。关键别混口径：
   `72/161` 和 `+2.8` 只属于内部集，不是 ClawEval。
```
