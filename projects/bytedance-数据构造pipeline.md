## 一、项目定位：把数据生产从"人工全流程"迁移到 Human-in-the-loop DAG

一句话定位：

> **把"人工寻源 → 手工出题 → 手工写 CoT → 手工填表"的数据生产过程，拆成一条可自动化的 DAG，机器负责高吞吐的候选生成与预处理，人工保留终版审核和高风险样本兜底。**

不是"我写了一个爬虫"，而是：

```text
原流程（纯人工）：找视频 → 出题 → 写 CoT → 填作业表 → 交付
                （每一步都靠人，吞吐低、标准不一致）
                        ↓
目标流程（借鉴 ReWatch-R1 重构后的半自动 DAG；Caption 与级联过滤节点待实施验证）：
关键词/考点寻源 → 抽帧预检 → TOS 入库 → 视频去重
→ 时间戳 Caption → 自动生成 Prompt/Answer → 自动生成证据 CoT
→ 飞书作业表自动填写 → 人工终审 → 交付
（机器做高吞吐候选与预处理，人工只做终审与兜底）
```

## 二、Pipeline DAG（节点与产出）

```text
[1] 寻源 Sourcing（能力驱动，非纯关键词）
    ├── 输入：Benchmark 弱项 → 能力维度 → 数据缺口 → 检索策略
    ├── 动作：按考点/能力从 YouTube / B 站等检索候选视频；
    │        个别任务再切分 / 拼接 / 合成以满足难度与配对要求
    └── 产出：候选视频 URL + 元信息（来源、时长、类型）

[2] TOS 入库 Ingestion
    ├── 动作：候选视频落对象存储（TOS），登记 sample_id 与元数据
    └── 产出：可寻址的视频资产 + 索引记录

[3] 去重 Dedup
    ├── 动作：视频级去重（避免重复素材稀释多样性、污染评测）
    └── 产出：去重后的候选池（去重难点见第四节）

[4] 生成时间戳 Caption
    ├── 动作：语义分段、片段级细描述、相对时间戳转绝对时间戳
    └── 产出：可供出题、答案校验和 CoT 引用的共享证据底座

[5] 自动生成 Prompt / Answer
    ├── 动作：按能力维度和 detailed/summary 信息差生成任务并过滤捷径
    └── 产出：带 required evidence 的问题与参考答案

[6] 自动生成初版 CoT
    ├── 动作：模型生成"定位→取证→对齐→推理→回答"的证据链
    └── 产出：Caption / Q / A / CoT 复合数据候选

[7] 飞书作业表自动填写
    ├── 动作：把候选三元组 + 视频链接自动写入飞书作业表
    └── 产出：可供人工审核的作业单

[8] 人工终审 Human Final Gate ← 本 Pipeline 的边界
    ├── 动作：终版审核、高风险样本兜底、难度/能力标签校准
    └── 产出：交付数据（进入下游质检 / SFT）
```

## 三、为什么不 100% 自动（Human-in-the-loop boundary）

保留人工终审不是妥协，是**合理的质量边界**：

```text
├── 自动生成 Prompt 容易语义漂移（问题跑偏、不可判、答案不唯一）
├── CoT 正确 ≠ CoT 可学习（形式对但训练信号弱，需人判"可学习性"）
├── 多视频题要求跨视频证据对应，机器难稳定保证"对应关系"成立
└── 难度对齐很难靠单模型 confidence 判断（易发生"难度坍缩"）

结论：自动化初版 + 人工终版 是当前合理的 human-in-the-loop boundary
     —— 机器提吞吐，人守质量下限。
```

## 四、工程要点与难点

```text
视频去重的难点：
├── 同源不同清晰度 / 剪辑片段 / 转码后哈希变化 → 精确哈希失效
├── 需要感知级去重（关键帧特征 / 近重复检测），成本更高
└── 去重不足 → 素材重复稀释多样性、甚至污染评测集

DAG 工程六维度（可展开的工程深度）：
├── 幂等性：同一候选重复入库/生成不产生脏数据
├── 断点续跑：某节点失败可从断点恢复，不整批重来
├── 错误隔离：单条候选失败不阻塞整批管线
├── 可观测性：每条数据的状态流转可追踪
├── 背压：上游高吞吐不压垮下游生成/写表
└── 状态管理：候选从寻源到交付的完整状态机
```

## 五、指标：Data Efficiency（比"生产了多少条"更重要）

```text
不要只报："我们生产了 400 条。"
应报：
├── Data Efficiency = ΔBenchmark / Effective Training Samples
├── Label Efficiency = ΔBenchmark / Human Hours
└── 因为最终价值是"少量高质量靶向数据 > 大量无策略数据"
     —— 管线的目标是提高"有效训练数据的供给效率"，不是堆量。
```
