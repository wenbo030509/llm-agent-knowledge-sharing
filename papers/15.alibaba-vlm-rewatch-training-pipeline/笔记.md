## 一、文章在讲什么（30 秒版本）

复杂视频推理落后于图像推理，**根因是数据瓶颈**：现有开源视频数据有三宗罪——① 整体式、无时间戳的 caption（抹掉时序结构）；② 简单的感知类 QA（看短片段或靠文本先验就能答）；③ 视觉不忠实的 CoT（靠常识和排除法凑答案）。于是 SFT 学不到"真正基于视频的推理"，RL 也因为缺可靠过程奖励而无法惩罚幻觉。

作者造了 **ReWatch 数据集（10k caption / 170k QA / 135k CoT）**，用三阶段合成管线解决上述三宗罪，再用 **SFT 冷启动 + GRPO（配 O&R 过程奖励）** 训出 ReWatch-R1，在五个视频推理 benchmark 上取得 SOTA 平均分。**一句话：这就是把"数据正确 ≠ 训练信号正确"落到视频领域的一套完整工程 + 实验闭环。**

## 二、核心观点（带面试说法）

```text
1. 数据瓶颈的三宗罪 = 我项目质检维度的镜像
   [面试说法] 无时间戳 caption→时序丢失；简单 QA→语言捷径；不忠实 CoT→证据幻觉。
              这正好对应我 pipeline 的三条质检规则：难度对齐、必须依赖视觉、证据忠实。
              ★ 我"凭经验"设的质检维度，在这篇里被写成了数据集设计的第一性原则。

2. Stage 1 分层动态帧率 Captioning（先把视频变成"带时间戳的结构化文本底座")
   [面试说法] 先用轻量 LVLM 低帧率做语义分段（保事件完整），再用强 LVLM 高帧率
              对每段生成带相对时间戳的事件描述，最后把相对时间戳realign成绝对时间戳。
              产出 = 全片带绝对时间戳的事件流 C_detail。
   ★ 关键设计：分段用便宜模型、细描述用贵模型——成本/质量分层，和我"抽帧判断前置省抓取"同构。

3. Stage 2 对比式出题 + 三层过滤（反捷径的核心）★★
   [面试说法] 先用 C_detail 生成一个"精简摘要 C_sum"，再让出题模型造出
              "能从详细caption答、但从摘要答不出"的题（对比式prompting逼出细粒度）。
              然后过三道 Filter：
              F1 答案验证：verifier 核对答案能否被 C_detail 支持（去错标）；
              F2 文本偏置消除：一组 LLM 不看视频作答，命中率 < θ_text 才通过（去文本先验捷径）；
              F3 摘要偏置消除：一组 LLM 只看摘要作答，命中率 < θ_sum 才通过（逼细粒度视频依赖）。
              10 种题型保多样性；过滤后 85k 题被改写成多选，扩到 170k QA。
   ★★ 这就是我说的"必须依赖视觉"的可执行版：F2 去语言捷径、F3 去粗粒度捷径——
      用"多个模型答不出"作为 video-dependency 的操作化定义，比人工判断可规模化。

4. Stage 3 多智能体 ReAct 合成 CoT（把"re-watching"过程外化）★★
   [面试说法] 两个 agent 在文本上模拟人"回看视频找证据"：
              Reasoner 产出 thought + action；Observer 在 C_detail 上执行 action 返回观察。
              两个核心动作：segment_retrieval(query)=按语义找事件时间戳（模拟找片段）；
              segment_query(timestamp)=按时间戳取事件细节（模拟定格看细节）。
              循环到给出答案，轨迹再转成带 <action>/<observation> 标签的自然语言 CoT。
   ★★ 这解决了"CoT 可学习性"：教的是"先定位→再取证→后推理"的证据组织框架，不是答案。
      且全程在文本 caption 上跑，成本极低——这是"合成"而非"人工标注"的降本关键。

5. 训练：SFT 冷启动 + GRPO + O&R 过程奖励
   [面试说法] SFT 用全部三部分数据，含 thinking / non-thinking 两模式（先学格式与grounding）；
              RL 用 GRPO，核心是 Observation & Reasoning(O&R) 奖励——
              不只看最终答案对不对，还看"中间观察是否被视频支持 + 推理能否从观察推出答案"，
              直接惩罚幻觉。base model = Qwen2.5-VL。
   ★ 这正好回答我项目里"为什么止于 SFT、后面怎么上 RL"：需要一个能验证"过程忠实"的 reward，
      O&R 就是把我 rubric 里"证据真实性"这条做成了 RL 的可验证奖励。

6. 数据集三件套是"紧耦合"的，不是三堆独立数据
   [面试说法] Caption 是底座 → QA 从 caption 长出来 → CoT 又基于 caption 生成推理轨迹。
              同一份带时间戳的结构化 caption 贯穿始终，保证 QA 和 CoT 都可追溯到同一证据源。
   ★ 对我的启发：数据 schema 要有"共享证据锚点"，否则 QA 和 CoT 各说各话、无法交叉校验。
```

## 四、真实结果与消融（原文 Table 1 + Fig 5/6/7）

### 4.1 五个视频推理 benchmark（注意：不是经典 Video-QA 基准，是 2025 新的高难推理基准）

> **VCR-Bench / MINERVA / Video-Holmes / Video-MathQA / CG-AV-Counting**，全部 192 帧评测、thinking 模式。

主结果（192 帧，Average，摘自 Table 1）：

```text
模型                         Average
Qwen2.5-VL-7B（base，非thinking）  30.71
Video-R1                          31.00
LongVideoReason-SFT*              26.31
ReWatch-R1-SFT（仅SFT）            33.25
ReWatch-R1（SFT+RL）               34.86
ReWatch-R1 + O&R（完整）           35.51 ← SOTA（同尺寸）
```

每项分数（192 帧，ReWatch-R1 + O&R）：VCR-Bench **40.43** / MINERVA **36.05** / Video-Holmes **43.88** / Video-MathQA **31.67** / CG-AV-Counting **25.51**。384 帧设置下完整版 Average **35.78**，同样是同尺寸 SOTA。

### 4.2 消融——四条可直接搬进我项目叙事的结论

```text
① 高质量 CoT 数据是关键：仅 SFT 的 ReWatch-R1-SFT(33.25) 就超过
   Video-R1-SFT(29.74) 和 LongVideoReason-SFT(26.31)——同样训练配置，赢在数据。
② RL 解锁进一步提升：33.25 → 35.51；SFT 教 CoT 的"形"，RL 教"神"（更忠实的推理）。
③ "会思考"依赖"学过怎么思考"：未训练的 base 直接开 CoT 反而更差
   （thinking 27.54 < non-thinking 30.71）——CoT 会诱发幻觉；只有训练后 thinking 才占优。
   ★ 这条直接反驳"加了 CoT 就更好"，是我 rubric"CoT 可学习性"的实验证据。
④ 高质量 QA 对 RL 同样关键（Fig 5b）：只用 Video-R1-QA / LongVideoReason-QA(各10k) 做 RL
   得分最低（all 42.0 / reasoning 34.3 / understanding 51.7），换成 ReWatch-QA 明显更高。
   且没有 SFT 直接 RL 会灾难性掉分——RL 需要强初始策略。
```

### 4.3 反捷径的量化铁证（Fig 6a，最值得我引用）★★

```text
                    ReWatch-QA   Video-R1-QA
推理步数（越多越难）    3.31         1.82
回答长度              398.75       205.74
Text-Only 准确率      29.4%        68.9%   ← 关键！
```

**Video-R1-QA 有 68.9% 的题不看视频就能答对（接近"泛滥的语言捷径"）；ReWatch-QA 只有 29.4%，接近 25% 随机基线**——证明三层过滤真的把"文本捷径"挤掉了，逼出真视频依赖。这就是我"必须依赖视觉"质检规则的**可量化验收指标**：拿一组纯文本 LLM 去答，命中率越接近随机越好。

### 4.4 RL 让推理"更准且更省"（Fig 6b / Fig 7）

- Fig 6b：SFT 阶段 action 数和准确率一起涨；RL 阶段**准确率继续升、平均 action 数反而降**——RL 在剪掉冗余步骤、聚焦关键动作。呼应我之前说的"工具调用降但完成率升 = 效率提升不是能力退化"。
- Fig 7：non-thinking 在 SFT 期涨得快，thinking 涨得慢；但 RL 之后 thinking 反超所有任务——说明**SFT 教格式、RL 教因果**，显式分步推理经过 SFT→RL 才是复杂视频任务的最优解。

**Fig 18 Answer Judge Prompt 原文要点（判"答案是否一致"，非判观察忠实）：**

```text
角色：你是帮我判断"模型生成答案"是否与"标准答案"一致的 AI 助手。
输入：Standard Answer（标准答案）、Model Answer（模型答案）
任务：判断两者是否一致；判定标准 = 只要表达的含义相同即算一致（consistent）。
输出格式：
  1. 一致输出 1，不同输出 0；
  2. 直接只输出 1 或 0，不要任何其他内容。
模板变量：Question:{question} / Model Answer:{extract_answer} / Standard Answer:{gt_answer}
```

★ 对我项目的启示：ReWatch 把"证据忠实（r_obs）"**做进了 reward 的数学定义**（对每条 observation 判是否被 caption 支持），

   这反而是我 rubric"证据真实性"可以深耕、形成差异化的点。
