# 每日记录 - 2026-09-28

> 主题：广告×交易数据互通——一个"听说来的业务"如何展开成完整商业逻辑。
> 今日收敛：把一段被压缩的商业判断（背景→目的→动作→收益）还原成可讨论的结构，
> 并从中挖出三个技术深挖点。**本文是二手信息的学习演练，不是我参与的项目**（边界见第五节）。

## 一、起点：一句被压缩的话

听到的原话：

> 「广告和交易是两个大部门，数据不互通，老板希望数据互通，实现用户数据联通，
> 通过行为数据形成行为数据标签，实现更精准的策略，提升转化和收益。」

**第一反应：这是一条完整的商业逻辑链，但中间被压缩了至少四个环节。** 老板说的是结果，
从"组织割裂"到"收益提升"之间省略了：为什么不通、打通什么、标签怎么定义、策略怎么落地、收益怎么验证。

```text
【听到的】数据互通 → 标签 → 精准策略 → 提升转化和收益
【还原后】组织割裂 → 数据割裂 → 用户视图割裂 → 策略只能做"半程"
              ↓ 打通
         ID 打通 → 行为融合 → 标签体系 → 策略升级 → 收益
```

**一句话抓本质**：广告只知道"用户点了"，交易只知道"用户买了"，
**没人知道"点了广告的那个人后来买了什么"**——同一个用户在两个部门眼里是两个"半身人"。

## 二、展开：背景 / 目的 / 动作 / 收益

**背景的三层原因**（难度递**减**，注意方向）：

| 层面 | 原因 | 难度 |
|------|------|------|
| 组织层 | 两个独立 BG，数据既是资产也是壁垒；"我的数据变公共资源，收益算谁的" | 最难（无标准答案） |
| 技术层 | ID 体系不同（设备维度 vs 账号维度）、数仓/埋点/时效不同（100ms vs T+1） | 中（有确定解） |
| 合规层 | PIPL、授权脱敏、ID 关联的隐私红线、商家数据敏感 | 一票否决 |

**关键判断：真实项目里卡住进度的大多不是技术，是组织和合规。** 技术问题有确定解，组织利益分配没有。

**目的的五层**：破孤岛（ID 打通）→ 汇行为（统一事件模型）→ 建标签（老板说的"行为数据标签"）
→ 升策略（广告深层出价 + 交易冷启动）→ 收收益（双增）。

**「行为数据标签」必须定义清楚**（老板没说，但这是项目能不能落地的关键）：
分事实/规则/模型三类，**三类评估口径完全不同**——事实看准确率、规则看业务合理性、模型看 AUC + 增量价值。

**动作的三层**（真实依赖顺序，不能跳）：
L1 数据层（ID-Mapping + 合规 + 统一事件模型 + 双链路 + Feature Store）
→ L2 标签层（生产/治理/服务化/权限）
→ L3 策略层（广告深层出价 + 交易冷启动 + 验证）。
节奏分 P0 合规打通 → P1 标签 MVP → P2 策略应用 → **P3 双向互喂**。

**P2 是生死线**：P0/P1 是成本中心，只有 P2 跑出一个被验证的收益案例，项目才从"数据中台"变成"业务引擎"。

## 三、三个技术深挖点

### 1. ID-Mapping：不只是 join 两张表

```text
建图 G=(V,E)：V = 各类 ID（device/user/phone_hash/pay/ad），E = 可观测关联边
求解：连通分量（Union-Find / Spark GraphX ConnectedComponents）
```

三个必须处理的坑：**① 传递闭包过度合并**（A~B~C ⇒ A~C 但强度衰减 → 限跳数 2-3 跳 + 边带置信度）
**② 冲突消解**（一台设备登录 5 个账号 = 家庭共用还是黑产？）
**③ 评估缺 ground truth**（用"同一订单里的 device 与 user"这类天然成立关联造正样本）。

> ★ 这和我在 CoT 质检项目里的 **Cascading Classification** 是同一个思路：高置信规则先过、
> 低置信走模型、最后人工兜底。质量和成本的分层是通用模式，不是两个领域的知识。

### 2. 延迟反馈：观测标签是被截断的

```text
曝光 t 时刻，成交可能 t+7d；但 t+1 训练时标签仍是"负"——实际是"未知"被当成"确定不买"
数学刻画：ỹ = y · 1{τ ≤ e}   （τ = 转化延迟，e = 已观测时长）
```

**危害不是"少了几条正样本"，而是每条假负样本都在教模型"这类人不买"→ 系统性压低出价
→ 广告主拿不到量 → 预算流失。** 三解对比：等待窗口（简单但新鲜度差）/ 延迟反馈模型 DFM
（联合建模 P(转化) 与 P(延迟|转化) + importance weighting）/ 短窗口 + 概率校准。

### 3. ★ 相关性 ≠ 增量：Uplift 建模（今天最深的一层）

```text
数据互通让我们看到"谁买了"
但投放要准，需要知道"谁因为广告才买"——这是两件事

用户四分：说服型（广告有用）/ 自然转化型（本来就买）/
         无动于衷（投了没用）/ 反感型（投了更差）
→ 只有"说服型"是广告的真实增量

混淆变量陷阱：观察"广告域活跃的用户交易域也买得多"
  诱人结论：广告有效
  真相：可能只是"高消费用户本来就既爱看广告又爱买"
```

对策工具箱：AB 实验（黄金标准但广告有 spillover 和滞后效应）/ PSM / DID / Uplift 模型（Causal Forest）。

**为什么这层最重要**：别人讲数据互通停在"打通 ID、建了标签、上了定向"，
往下讲一层"我们优化的到底是相关性还是增量"——**这是策略 PM 和数据分析师的分水岭。**

## 四、和职业主线的咬合（今天的核心收获）

```text
① 这是「数据策略五问」在广告×电商域的实例
   采什么 / 从哪采 / 怎么用 / ★怎么验证★ / 优先级

② 评测与实验 = 这条链的最后一环 ← 我的差异化定位的具体战场
   数据互通了、标签建好了、策略上线了——
   "怎么证明它真的带来收益"就是实验设计的活。
   这正是「评测 × 数据交叉点」的落点。

③ 方法论可直接复用，不是新学一套
   Cascading Classification → ID-Mapping 的分层置信合并
   能力 gap 驱动            → 归因断裂是这个 gap 的补法
   评测驱动闭环             → 与本文 L3"验证"环节同构
```

**面试锚点**（今天提炼的表述）：

> 「这类数据互通项目的关键判断是：**数据打通本身不产生收益**，收益来自
> "标签质量 × 策略设计 × 实验验证"三段接力。而且打通的终点不是"知道谁买了"，
> 而是"知道谁因为广告才买"——这是相关性到增量的跨越，得靠 Uplift 建模和严格的实验设计。
> 这正好是我擅长的部分：把数据资产变成被验证过的收益。」
